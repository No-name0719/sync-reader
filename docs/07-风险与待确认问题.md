# 07 - 风险与待确认问题

> **TL;DR**：本文汇总规划阶段的全部**默认假设（A）、待用户确认的问题（Q）、技术/产品风险（R）**。任务书未明确之处均按合理默认推进（对应各 A 条目），任何 A/Q 的变更都会波及"影响范围"列所指的文档。无其他未登记的隐含假设。

| A14 | 使用设备本地时钟，不做 NTP 校验；时钟回拨由 rev 单调性兜底 | [04 §6.2](./04-同步引擎与冲突解决.md)、R7 |

| A16 | 元数据、library.json 等云端文件**不做端到端加密**（坚果云/自建服务器可见书名与进度；正文文件本身原样存储）。若需要 E2EE 属大版本特性 | Q13 |
| A17 | **M4 首发范围拍板（2026-10-28）**：FR-107 分组标签与 FR-209 音量键翻页纳入首发（音量键默认关；亮度调节不实现）；FR-210 书内全文搜索不进首发（登记后续迭代）；Windows 双形态分发（Inno Setup 安装器 + zip 便携包）；许可证 MIT、正式名沿用 SyncReader（Q1/Q2 拍板见 §2） | [01 §3](./01-需求规格说明.md)、[09](./09-发布与分发.md) |

## 3. 风险登记（R）

| ID | 风险 | 概率 | 影响 | 缓解措施 | 影响范围 |
| --- | --- | --- | --- | --- | --- |
| R1 | Flutter 桌面侧关键插件（window_manager/file_picker 等）成熟度或维护中断 | 中 | 中 | 只选高星活跃插件；M1 里程碑做插件可用性验证；必要时收编 fork | [02 §D1](./02-技术选型.md) |
| R2 | epub 自研分页/渲染引擎工作量超预期，复杂书籍渲染缺陷 | 中高 | 高（核心体验） | **方案已落地（M3 Phase A，2026-10-28）**：epub_pro 解析 + flutter_widget_from_html 逐块渲染；分页 = 连续排版 + 视口高度 snap 翻页（不做块内绝对分栏，locator 仅依赖块坐标不受影响）；复杂表格/浮动布局**降级为顺序文本**（保留单元格文字、块标 degraded，解析失败整体降级不阻塞打开）。WebView（epub.js/foliate-js）兜底保留为"复杂书兼容模式"后备，暂不引入 | [02 §D2.1](./02-技术选型.md)、[05 §3.3](./05-元数据Schema与云端目录布局.md) |
| R3 | 坚果云 WebDAV 行为与文档预期不符（ETag 支持、MOVE、限流阈值、配额政策收紧） | 低（**M2 已实测化解**，2026-10-27） | 高（模式 a 可用性） | **实测结论**：ETag（22 位类 base64 无引号，非 MD5）✅、If-None-Match 304 ✅、MOVE 201 ✅、Range 206 ✅、PROPFIND 小写 `d:` ✅、gzip 未启用（meta 本就 KB 级，无碍）；两个非标准行为已适配：缺失目录 PROPFIND 回 **409**（非 404，适配器已容忍+离线回归）、MKCOL 既有目录回 **201**（非 405，幂等语义不受影响）；PUT 不回带 ETag → 清单写后补拉一次 meta（KB 级可接受）。实测画像与双端收敛预演固化为 `webdav_jianguoyun_profile_test.dart`（凭据缺失自动跳过）；额度参数可配置（A7）。**残余风险**：请求频率/流量限额未见官方文档数值，极端高频场景可能触发临时 410 风控（探针曾复现，keep-alive 常规节奏未复现）；gzip 缺失使清单体积无压缩 | [04 §8](./04-同步引擎与冲突解决.md)、packages/sync_core/test/backend/webdav_jianguoyun_profile_test.dart |
| R4 | flutter_markdown_plus 长期维护不确定（官方 flutter_markdown 已停维的连锁） | 中 | 低 | 必要时 fork 收编进 monorepo（该包体量小）；备选方案 B（markdown→HTML→widget 渲染）已在 [02 §D2.3](./02-技术选型.md) | [02 §D2.3](./02-技术选型.md) |
| R5 | pdfium 使安装包 +6-10MB/ABI | 确定 | 低（可接受） | Android 按 ABI 拆分 APK；目标 60MB 内仍有余量（NFR-04） | [01 NFR-04](./01-需求规格说明.md) |
| R6 | 各 WebDAV 实现（群晖/Alist/Nextcloud 等）行为差异（MOVE/ETag/gzip/并发限制）造成兼容 bug | 中 | 中 | 官方只背书坚果云（Q10）；BackendAdapter 内置能力探测（连接时探测 MOVE/ETag 支持，逐项降级）；契约测试多实现样本 | [03 §4.3](./03-系统架构设计.md) |
| R7 | 设备时钟大幅偏差导致 LWW 结果与用户直觉相反（"刚读的没生效"） | 低 | 中 | rev 单调性保证正确性（A14）；检测系统时间异常并提示；设置页"以本设备为准"强制覆盖按钮 | [04 §6](./04-同步引擎与冲突解决.md)、[02 §D6.2](./02-技术选型.md) |
| R8 | 国产 Android 厂商激进杀后台，后台同步不可达 | 高 | 低中（体验） | 同步主战场放在前台（启动/回前台/阅读中防抖）+ 网络恢复触发；后台任务作为增强；README 提供白名单设置指引 | [04 §3](./04-同步引擎与冲突解决.md) |
| R9 | 移动网络下误下大文件烧流量 | 中 | 中 | "仅 Wi-Fi 下载正文"默认开启；单文件 >50MB 双重确认；坚果云配额闸门 | [04 §8.3](./04-同步引擎与冲突解决.md) |
| R10 | 自研 WebDAV 客户端（PROPFIND XML 等）实现缺陷 | 中 | 中 | 范围收敛（只用 PROPFIND/GET/PUT/MOVE/MKCOL/DELETE 六动词）；坚果云真实响应样本录制进契约测试 | [02 §D7](./02-技术选型.md) |
| R11 | SQLite 文件损坏导致书库/进度丢失 | 低 | 高 | WAL 模式；应用内"导出书库备份"（meta JSON + 书单）功能（P1）；云端 meta 本身即备份（重新接入即重建本地库） | [05 §5](./05-元数据Schema与云端目录布局.md) |
| R12 | 自建服务器暴露公网被攻击（弱口令/未授权访问） | 中 | 高 | 默认关注册（REGISTRATION_OPEN=false）；Argon2id；每设备 token 可吊销；限流；文档强烈建议 Tailscale 或 Caddy HTTPS；明文 http 需显式确认 | [06 §3/§4.3](./06-自建服务端设计与部署.md) |
| R13 | 双端同时修改书籍信息（改名/换文件）+ 进度的组合冲突结果不直观 | 中 | 低 | v1 整框架 LWW 可预期；Q5 若拍板拆分则 v2 实现字段级冲突域 | [04 §6](./04-同步引擎与冲突解决.md) |
| R14 | 中文字体度量跨设备差异造成分页/percent 漂移 | 高 | 低 | locator 记录逻辑坐标（章节+字符偏移），percent 仅兜底，机制上免疫（[02 §D1.2-R2](./02-技术选型.md)） | [05 §3.3](./05-元数据Schema与云端目录布局.md) |
| R15 | **pdfrx 版本受本机环境多重约束**（M1 已全部化解，登记备查）：① 2.x 依赖 pdfium_dart 的 native assets 钩子，Windows 上需编译 C 门库，而本机 HKLM cmd `AutoRun = "chcp 65001"`（无 `>nul`）污染 vcvars64.bat 探测（修复需管理员，见 [08 §6.4](./08-开发环境搭建.md)）；② 1.3.5（最后一个 1.x）有一处 Dart 3.13 流分析不兼容；③ 其 Windows/Android CMake 均强制创建符号链接（需开发者模式）；④ 应用模板的 install 前缀守护会被嵌套插件 `project()` 重置（与 pdfrx 组合才暴露）；⑤ 本机直连 GitHub 下载 pdfium 中途断流 | 确定（已发生并修复） | 中 | 已将 1.3.5 收编进 `packages/third_party/pdfrx` 并打 3 处带 `SyncReader patch` 注释的补丁：Dart 3.13 兼容（`pdf_file_cache.dart`）、Windows CMake junction/拷贝降级（`windows/CMakeLists.txt`）、Android CMake junction 降级 + `.lib` 持久缓存（`android/CMakeLists.txt`，注意 `WIN32` 是目标系统变量须用 `CMAKE_HOST_WIN32`）；`apps/sync_reader/windows/CMakeLists.txt` 前缀逻辑前置；免开发者模式构建与 pdfium 预置脚本见 [08 §6.3](./08-开发环境搭建.md)。升级路径：管理员修复 AutoRun + 开发者模式 → 评估 pdfrx 2.x → 移除收编副本 | apps pubspec、windows/CMakeLists、CI、pdf 阅读器 |
| R16 | **flutter_secure_storage_windows 编译依赖 ATL**：上游 4.2.2 使用 `atlstr.h`（CA2W/CW2A 转换类），本机 VS Build Tools 无 ATL 组件且静默安装需管理员，无人值守无法安装 | 确定（已发生并修复） | 中 | 已收编进 `packages/third_party/flutter_secure_storage_windows`，唯一 ATL 依赖以 Win32 API 等价实现替换（`SyncReader patch` 块见该包 `windows/flutter_secure_storage_windows_plugin.cpp`，UTF-8 BOM 保存），pubspec `dependency_overrides` 指向；升级路径：安装 ATL 组件后评估回退上游（同 pdfrx 收编先例 R15） | apps pubspec、Windows 凭据存储（DPAPI） |
