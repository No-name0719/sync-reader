# 10 · 界面重设计方案（v1.0.0 之后）

> 状态：**已实施（2026-10-29，v1.1 开发完成，待真机/桌面逐屏验收）**。实现与原型/决策的出入统一记在 §9 实施记录；`ui_prototype/` 原型保留作设计依据，不再随实现演进。
> 目标：把 SyncReader 从「能用」提升到「愿意每天用」——书库要像书架，阅读器要像书，同步要像后台而不是噪音。

## 1. 现状审计（v1.0.0 真机截图 + 源码）

在 Windows 12 / 2560×1440 上跑 `build/windows/x64/runner/Release/sync_reader.exe` 抓图，对照源码逐屏走查，结论如下。

- 封面角标 9px、`SyncBadge` 用 `Colors.orange.shade700` 等 Material 散色，与主题脱节。

- 危险操作（清除凭据、删除）与常规项混在同一列表，无视觉分区。

## 2. 设计目标

1. **书库像书架**：一眼看完「有多少本、读到哪、哪些没同步」，而不是「一堆文件」。
2. **阅读器像书**：正文是主角，控件是配角，随时可隐去。
3. **同步是后台**：状态常驻可见但不喧哗；异常才升级为提示。
4. **一套令牌，全局一致**：色彩/字阶/间距/圆角全部集中定义，Flutter 侧落地为 `ThemeExtension`。
5. **跨端自适应**：桌面宽屏用左栏 + 多列；窄窗收成图标栏；移动端改底部标签栏。

## 3. 设计系统

完整可视化见原型「设计规范」页（`ui_prototype/index.html` → 顶部「设计规范」）。

### 3.1 色彩

中性色**带暖调**（纸感），品牌色沿用 teal 但加深降饱和，摆脱 `colorSchemeSeed: Colors.teal` 的塑料感。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#F6F5F1` | `#121317` | 应用底色 |
| `--surface` | `#FFFFFF` | `#1A1C21` | 卡片 |
| `--surface-2` | `#FAF9F6` | `#212429` | 次级填充 |
| `--border` | `#E4E2DB` | `#2C3038` | 1px 描边 |
| `--text` | `#1D1C1A` | `#E9E7E2` | 主文字 |
| `--text-2` | `#6A6862` | `#9EA2AB` | 次要文字 |
| `--success/--warn/--danger` | `#1F7A4D` / `#A95B06` / `#B42318` | 对应提亮版 | 状态语义 |

**品牌风格（accent）可切换**，默认**赭石**（纸墨暖调），用户可在「设置 → 外观」中改。

| 风格 | 浅色主色 | 深色主色 | 气质 |
| --- | --- | --- | --- |
| **赭石（默认）** | `#B25430` | `#E08A62` | 纸墨暖调，贴「读书」这件事 |
| 青瓷 | `#0E7A6E` | `#35B8A3` | 清冷沉静（原 teal 基因，去饱和） |
| 墨绿 | `#2F5D4F` | `#6FBB9F` | 线装书气质 |

每套 accent 含 5 个变量：`--brand` / `--brand-hover` / `--brand-soft`（选中底色）/ `--brand-soft-2` / `--brand-text`（软底上的可读文字色）。
Flutter 侧落为一个 `AppAccent` 枚举 + `ThemeExtension`，持久化到新增的 `app_settings` 表（只增不删迁移）。

**阅读主题独立于应用主题**（可在阅读器内单独切换）：

| 主题 | 背景 | 正文 | 说明 |
| --- | --- | --- | --- |
| 纸白 | `#FFFFFF` | `#26251F` | 默认 |
| 米黄 | `#F6EFE0` | `#40382B` | 旧版「纸张」的升级 |
| 护眼 | `#E5EEE2` | `#2B3529` | **新增**，淡绿护眼 |
| 夜间 | `#14151A` | `#C8CACD` | 比旧版 `#121212` 更柔和 |

### 3.2 字体

**不打包中文字体**（体积代价 17–25MB，与 NFR-04 体积门冲突），全部走系统字体栈：

- **UI**：`Segoe UI Variable`（Win）/ `Roboto`（Android）+ CJK 交给系统（微软雅黑 / 思源黑体）。
- **阅读正文**：`Noto Serif SC` / `Source Han Serif SC` / `Songti SC` / `SimSun` → 宋体阅读感。
- **可选第三档**：`KaiTi` / `STKaiti` 楷体。

字阶（UI 基准 14px）：

| 名称 | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| display | 30/38 | 680 | 书名、页面主标题 |
| h1 | 22/30 | 620 | 章节标题 |
| h2 | 18/26 | 650 | 页面标题、卡片标题 |
| h3 | 15/22 | 620 | 分组标题 |
| body | 14/22 | 400 | 正文、列表主行 |
| sm | 13/20 | 400 | 次级正文 |
| caption | 12/18 | 400 | 辅助说明 |
| micro | 11/16 | 600 | 标签、角标 |

**旧版 9px/10px 角标全部上调到 11px 以上。**

### 3.3 间距与圆角

- 间距 4px 基准：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。
- 圆角：`6`（chip）/ `10`（按钮、封面）/ `14`（卡片）/ `20`（大面板）。
- 阴影：三级极浅投影（`0 1px 2px` → `0 14px 36px`），层级主要靠表面色差 + 1px 描边。

## 4. 页面方案

### 4.1 应用外壳（新增）

- **桌面 ≥1180px**：左侧导航栏 232px（品牌区 / **书库 · 同步 · 设置** / 底部同步状态胶囊）。
- **窄窗 1180px 以下**：导航栏收成 68px 图标栏。
- **移动 ≤860px**：隐藏侧栏，改底部标签栏（书库 / 同步 / 设置）。
- 顶栏统一：页面标题 + 副标题 + 右侧动作区，1px 底边线。
- **导航只保留三项**：「工具」分组与工具索引页取消（见 §4.8）。原先散在工具组里的功能重新安置：
  - 导入 → 回到书库顶栏（分裂按钮）；
  - 未上传的书 → 同步页的「未上传的书」卡片；
  - 云端书库管理 → 同步页的「云端书库」入口 → 独立页。

### 4.2 书库

#### 两层筛选（取交集）

筛选拆成**两层**，两层**同时生效、取交集**（不是互斥四选一）：

| 层 | 控件 | 取值 |
| --- | --- | --- |
| 第一层 · 状态 | 常驻 chip 行（互斥单选） | `全部` / `已同步` / `仅本地` / `仅云端` |
| 第二层 · 分组 | 下拉菜单（互斥单选） | `全部分组` / `未分组` / 各分组 / `管理分组…` |

**第一层是四个互斥桶**（云端轴「云端有无」× 本地轴「本地正文有无」组合）：

| 桶 | 定义 | 封面角标 |
| --- | --- | --- |
| `已同步` | 云端有 + 本地有正文 | 阅读百分比 / `待上传` / `同步失败` |
| `仅本地` | 云端没有 + 本地有正文 | `仅本地` |
| `仅云端` | 云端有 + 本地没有正文 | `未下载` |

四态互斥、计数不重叠。**「已删除」的书（云端有墓碑、本地正文已删）落在 `仅云端` 桶，与普通占位书完全一样——书库视图不再区分它们。**

- **分组不再平铺**：分组数量不可控（用户可自建），平铺成 chip 行会挤爆版面，改为一个下拉。按钮上显示当前选中的分组名（`📂 小说 ▾`）。
- **计数是分面计数（faceted count）**：第一层 chip 上的数字 = 在当前分组筛选下该状态有多少本；第二层下拉里的数字 = 在当前状态筛选下该分组有多少本。两个数字互相联动，用户能提前看到「换一层会剩多少」。
- 右侧灰字给出结果概要：`共 42 本` 或 `匹配 3 / 42 本`。
- 两层交集为空时给出空态（图标 + 说明 + 「清除筛选」按钮），而不是一片空白。
- **旧版的「在读 / 未读」维度被移除**：在读与否是「进度」而不是「状态」，交给右上角「最近阅读」排序表达；混进筛选会让维度语义不清。

#### 书卡交互

- **点封面直接打开书**：书卡上没有任何常驻按钮，也不做 hover 浮层（旧版 hover 出「继续 / ⋯」浮层）。点击封面 = 打开该书（未下载的先触发下载，已删除的给出提示）。
- **信息入口改为手势**：
  - 桌面端 **右键** 书卡 → 弹出上下文菜单；
  - 移动端 / Pad **长按** 书卡 → 弹出同一个上下文菜单。
  - 菜单项：`继续阅读（xx%）` / `下载正文`（未下载时）/ `书籍信息` / `移动到分组…` / —— / `删除本书`（危险色）。
- **封面右上角状态胶囊**（取代旧版封面底部的黑色 `98%` 遮条）：
  - 已下载且在读 → **阅读百分比**（品牌色胶囊，如 `62%`）；
  - 未下载 → `未下载`（墨色胶囊）；
  - 本地已删除 → `已删除`；
  - 同步异常 → `待上传`（琥珀）/ `同步失败`（红）。
  - 卡片下方的文字行只留「⏱ 阅读时长」，百分比不再重复。
- **手势冲突（需注意）**：FR-107 现有「长按拖拽归组」与「长按出菜单」在触屏上冲突。
  **方案**：桌面端保留拖拽归组 + 右键菜单；触屏端取消拖拽归组，统一走菜单里的「移动到分组…」。

#### 其它

- 筛选从弹层改为常驻可见（旧版「全部 ▾」弹层），解决 I2。
- **生成封面改「纸底墨字」**：无真封面（txt / 部分 epub）时，不再用高饱和色块，改为**极低饱和的纸底 + 同色系深墨首字 + 内框线 + 标题/作者排版 + 品牌色小横线**。底色/墨色/框线由内容哈希取同一色相（饱和度 12%、亮度 90%），既保留每本书的辨识度，又不与赭石品牌打架。
- **网格**：卡宽 154px 起（`auto-fill minmax(154px,1fr)`），封面圆角 10px + 轻投影；hover 上浮 3px 并浮出「继续 / ⋯」操作条。
- **进度**：从封面底部的黑色 `98%` 遮条改为**封面下沿 3px 品牌色进度条**。
- **列表模式**：行高 78px，右侧 120px 线性进度 + 百分比；移动端隐藏进度条只留百分比。
- **状态角标**：`仅云端` / `待上传` / `同步失败` 统一为封面左上角胶囊（11px）。
- **同步状态条从内容区移出**，收进左下角胶囊；仅在配额超限/同步失败时，内容区顶部才插入提示条。解决 I1。
- **搜索框**在桌面进顶栏、在移动端落进内容区。

#### 导入（兼容单文件与批量）

- 顶栏导入按钮改为**分裂按钮**：主区「＋ 导入」= 导入文件；箭头展开「导入文件… / 批量导入（文件夹）」。单文件与批量两条路径在同一个入口下，不再散落在「更多」菜单里。
- **导入确认弹窗**（两条路径共用）：文件清单 + 「**同时上传到云端**」勾选（**默认勾选**）+ 上行流量预估（`预计上行 42.6 MB · 坚果云免费额度 1 GB / 月`）。取消勾选时提示切换为「不上传：不消耗上行流量，其它设备看不到这几本书」。
- 取消勾选导入的书标记为「仅本地」，封面右上角显示「仅本地」角标。

### 4.3 书籍详情

- Hero：大封面 168px + 阴影，右侧标题（display 30px）/ 作者 / 标签 / **进度条 + 「62% · 第 128 章」** / 主操作按钮组。
- 「阅读数据」卡片：4 个统计块 + 近 7 天阅读量柱状图。
- 「文件信息」卡片：定义列表（文件名/大小/哈希/添加时间/同步根）。
- 「目录」卡片：**新增目录预览**（旧版只给章数，目录完全在阅读页内）。

### 4.4 阅读器（改动最大）

- **默认沉浸**：进入阅读器只留正文，全部控件隐藏；**点击正文区域唤出/收起**控制条。首次进入给一条「点按屏幕中部显示菜单」的轻提示（2.6s 自动淡出）。这是通用手势，与 FR-209 音量键翻页并存。
- **默认分页**：翻页模式默认「分页」，与旧版默认「滚动」相反（评审决策）。技术书 / 长文可手动切滚动。
- **点击热区**：左右两翼各 22% 宽用于翻页，中间 56% 不拦截事件（保证正文仍可滚动与选中）。
- **正文排版**：衬线宋体、首行缩进 2em、两端对齐、正文列宽 720px、字号 19px、行高 1.95。
- **顶部条**：返回 / 书名 / 当前章 / 目录 / Aa 排版；**底部条**：章节名 + 进度滑块 + `62% · 第 12 / 34 页`。
- **Aa 排版面板**（桌面右侧抽屉 / 移动底部弹层）：实时预览框 + 字号 / 行距 / 页边距 / 字体（衬线·黑体·楷体，带预览）/ 4 种背景 / 翻页模式。解决 I4。
- **目录抽屉**：右侧抽屉，按层级缩进，当前章高亮并带「当前」标记。

### 4.5 同步设置

- 后端卡：坚果云标识 + 账号 + 连接状态胶囊 + 「重新配置」。
- 「立即同步」独立成行，右侧主按钮。
- 开关行统一「标题 + 说明 + 开关」。
- **流量面板**：上行/下行双条 + 80% 阈值刻度线 + 超限提示条。
- **「未上传的书」卡片**（新增）：列出「本地有、云端没有」的书（详见 §4.7c），每行一个「上传到云端」，卡片头部有「全部上传」。
- **「云端书库」卡片**（新增）：显示云端书的数量与占用，进入云端书库管理页（§4.8）。
- **维护区**与**危险操作区**拆成两张卡，危险区用红色描边 + 红色文字，与常规操作视觉隔离。
- **「云端孤儿清理」行删除**：语义不清（用户反馈），云端正文没有对应书目时直接清掉即可，不需要独立入口。

### 4.6 配置引导

旧版 `Stepper` 改为自绘**四步进度轨**（完成 ✓ / 当前 / 未开始），表单统一为标签 + 输入框 + 提示条。

### 4.7 设置（新增页面）

原应用没有设置页（同步设置兼作半个设置页）。新增后承担「外观 + 阅读默认值 + 存储 + 关于」：

- **外观**：主题风格三选（赭石 / 青瓷 / 墨绿，带配色预览）、外观模式（浅色 / 深色 / 跟随系统）——**即时生效，无需重启**。
- **阅读**：全局默认值（默认字体 / 字号行距 / 背景 / 音量键翻页）。
- **存储**：本地占用统计 + 清理缓存。
- **关于**：版本、MIT 许可、无账号无遥测声明。

### 4.7b 删除语义变更（本地删除不再保留正文）

**这是对 FR-408 / docs/04 §7.1.2 的一处需求变更，实施时必须同步改基线文档。**

| | 现状（docs/04 §7.1.2） | 变更后 |
| --- | --- | --- |
| 本地 `books` 行 | 删除（移出书库视图） | **保留**（`localPath` 置 NULL） |
| 本地正文文件 | 移入应用内「游离文件」区（不删盘） | **直接删除**（真正删盘，释放磁盘） |
| 封面文件 | 保留在游离区 | 随正文一并删除 |
| tombstone | 写 `deleted_books` + 推云端 | 不变 |
| 云端正文 | 永不删除 | 不变 |
| 其它设备收到 tombstone | 正文保留为游离文件 | 不变 |
| 该书在书库中的呈现 | 从书库消失 | **保留在书库里，落在「未下载」区** |

**为什么改**：`books` 表不允许加列（docs/05 §5 DDL 是同步语义的一部分），所以无法用「新列标记本地已删除」来区分「仅云端占位书」和「本地已删除书」。改为「删正文、留元数据」后，本地删除的书天然落进「未下载」区，不需要新的列，也不需要新增一个筛选维度。

**实施要点（三个必须改的地方，缺一个就会出问题）**：

1. `BooksDao.softDelete()`：改为 `UPDATE books SET localPath = NULL`（保留行）+ 删除正文/封面文件 + 写 `deleted_books` 墓碑；**不再删 `books` 行**，进度行保留（同文件重新导入后可恢复位置）。
2. `DriftLocalibrary.listBooks()`：**必须排除**在 `deleted_books` 里有墓碑的书。否则同步引擎会把这本书当正常书推回云端，与刚推上去的 tombstone 打架。
3. `DriftLocalLibrary.applyRemoteMeta(tombstone)`：**本端已发起的墓碑要幂等**——若 `deleted_books` 已有该 bookId 的记录（= 本端自己删的），再次收到该 tombstone 时**不要删 `books` 行**，否则下次同步会把保留的元数据抹掉，书就从书库消失了。本端未发起的（其它设备删的）才删行 + 正文转游离区。

**遗留语义（需在 docs/04 写明）**：本地删除的书会一直留在书库的「未下载」区，直到 tombstone 被云端 GC（90 天）后再拉到才会消失。

**UI 上不区分「已删除」与「未下载」**：两者的差别只存在于数据层（`deleted_books` 有没有墓碑），书库视图一律显示「未下载」角标、右键菜单给「下载正文」。用户不需要为「已删除」这个概念买单。

**重新下载一本已删除的书**：云端正文从不删除，所以正文仍能拉回本地；本地随即视为一本普通的「有正文」的书。墓碑仍在，因此它**不会自动复活到云端**——除非本地产生新的进度变更（`rev+1`）后推出正常 meta 覆盖墓碑，走 docs/04 §7.2 既有的「正常 meta 胜出即复活」语义。

**删除确认弹窗文案**（改）：

> 删除后的行为：
> · 本地正文文件**立即删除**（释放磁盘空间，**不可恢复**）；
> · 元数据保留，本书会移到书库的「未下载」区；
> · 删除标记会同步到云端，其他设备的此书也会从书库移除（它们的正文文件仍保留）。
>
> 不会删除你磁盘上的原始书籍文件。

### 4.7c 「仅本地 / 未上传」状态（新增概念）

**定义**：一本书**本地有正文、云端没有**，且本端**不会自动把它传上去**。
统一的心智模型：**「这台设备自己导入过一次，但没有上传」**。

**两种来源，用户看到的是同一个状态**：

| 来源 | 产生方式 | 内部状态 |
| --- | --- | --- |
| 导入时选「不上传」 | 导入弹窗取消勾选「同时上传到云端」 | 本地标记为仅本地（`local_only_books`），同步引擎完全看不见它 |
| 「从云端移除」后 | 云端管理里把书从云端删掉 | 云端 meta 已删且**不写 tombstone**；本端因仍有 `baseRev`，diff 落到**第 7b 行「云端缺失」→ 保留本地、不删不推** |

两种来源的反向操作都是「**上传到云端**」，恢复成正常同步的书。

**书库里的表现**：封面右上角「仅本地」角标；右键菜单有「上传到云端」/「设为仅本地（不上传）」。

**同步页的「未上传的书」卡片**列出两类：
1. **仅本地的书**（有书目行）→ 上传 = 解除仅本地标记 → 下次同步走 diff 第 7a 行「本端新书上架」→ 推 meta + 传正文；
2. **游离文件**（只有正文文件、书目行已随删除消失）→ 上传 = 按 `contentHash` 重新关联回书库（FR-408 既有挂回逻辑）+ 上架。

**实施要点**：

1. **新增本地表 `local_only_books(bookId)`**。`books` 表不允许加列（docs/05 §5 DDL 是同步语义的一部分），但有 `book_groups` 这个「纯本地、不同步」的先例，同样处理。需同步更新 docs/05 §5 与 `schemaVersion` 迁移。
2. `DriftLocalLibrary.listBooks()`：**必须排除**仅本地的书 → 它们永不进 diff → 既不推 meta 也不传正文。
3. `pushBookMeta()`：**必须跳过**仅本地的书 → 读进度时也不能把它顺手推上云（进度防抖路径 docs/04 §3 触发时机 3）。
4. 「上传到云端」= 删掉 `local_only_books` 行 + 触发一次全量同步 → diff 第 7a 行 → 上架 meta + 正文。
5. 「从云端移除」= 调 `BackendAdapter.deleteMeta(bookId)`（**不是** `deleteBook()`——后者是推 tombstone 的全局删除）。后端已有 `listMetas()` 与 `deleteMeta()` 两个能力（`backend_adapter.dart`），正好够用，无需新增适配器接口。
6. **副作用要写进文档**：从云端移除后，本端这本书落到 diff 第 7b 行，不会自动再上传；要恢复需「重新上架」（清掉 `sync_state` 的 `baseRev`）。

### 4.8 云端书库管理（新增页面，取代原「工具」三屏）

原「工具」分组（批量导入 / 游离文件管理 / 云端孤儿清理）与工具索引页**整体取消**，功能重新安置：导入回到书库、游离文件并入同步页的「未上传的书」、云端孤儿清理删除。新增**云端书库管理**页。

**为什么要有这个页**：书库里只有**本地有**的书；云端还有**别的设备上传的、你本地没有**的书。从云端视角清理书库是书库页做不到的。

- 顶部说明条（蓝）：「『从云端移除』只删掉云端副本：**各端本地文件保留、照常可读**，但也不会自动再传回云端；任一端都可以随时重新上传。」
- 列表每行：勾选框 + 书名 + 格式·大小 + 本地状态胶囊（`本地已下载` / `仅云端`）+ 「从云端移除」按钮。
- 底部操作条：已选数量 + 「全选」+ 危险色「从云端移除」。
- **删除语义**：只移除云端副本（`deleteMeta`），**不写 tombstone**；各端本地副本保留（见 §4.7c）。

**被取消的三屏**：
- 工具索引页 → 删除（导航只留三项）。
- 游离文件管理页 → 并入同步页「未上传的书」卡片（并新增「上传到云端」动作）。
- 云端孤儿清理页 → 删除（语义不清；云端无书目的正文直接清掉即可）。

**批量导入页保留**，入口改为书库顶栏分裂按钮（§4.2）。

### 9.2 与原型/决策记录的实现出入（按批交付记录汇总）

1. **txt 两端对齐（A10）**：核查确认 Flutter 3.47 的 `TextPainter`/`Text` 引擎级支持 `TextAlign.justify`（作用于软换行行，段末行左对齐——正是中文行为），txt 分页器按整块测量且测量/渲染同参数，故 **txt 实现了真两端对齐**，未降级。

13. **AppBar 标题字体修正**（本轮顺手修掉的真实瑕疵）：`AppBarTheme.titleTextStyle` 原本直接给裸 `t.h2`，会**丢掉** Material typography 合并进来的字体族（`englishLike` 默认 `Roboto`），导致标题字体与全站不一致——改为不覆盖该字段，由 Material 取 `textTheme.titleLarge`（已是本套 h2 的字号/字重/色）。
14. **字阶显式带字体族**（同一根因的全面修复）：字阶 `_style()` 现在带 `fontFamily: AppFonts.ui`（'Roboto'）。原先裸字阶样式（如 `SwitchListTile` 标题）会落到别的字体（Windows 上落 Segoe UI、测试环境落默认字体），与 `textTheme` 槽位不一致。Android 上 'Roboto' 即原生字体，Windows 上缺失时 Flutter 回退平台默认字体（Segoe UI）+ 系统 CJK 回补——观感与不设时一致，故可安全显式声明。
15. **同步设置页「测试连接」按钮**（用户反馈新增）：后端卡新增「测试连接」主按钮——**点击即测已保存的配置**，结果就地显示（逐步骤 + 往返延迟 + 能力摘要），不弹窗、不跳页、不改动凭据；原来的「重新配置」保留（走四步向导）。同时**移除维护区那个同名但行为不同**（点击跳转向导）的入口，避免「点一下就测」与「走一遍流程」两个同名入口并存。配置向导页另有「使用已保存的配置测试」快捷卡（不填表直接测）。
16. **凭据规范化**：写入前与读取时都对账号/密码做「去首尾空白 + 去零宽字符（U+200B-200D、U+FEFF）」，防手输/粘贴带空格导致 401；401 文案补一句「坚果云 WebDAV 只接受应用密码，账户登录密码一定会 401」。

### 9.4 逐屏比对材料（本地，不入库）

窗口实时截帧在本机开发会话不可用（Impeller 合成限制，客户端白屏——属截帧工具链问题，应用本体渲染正常），故改用**金测渲染**产出逐屏 PNG 作为与原型比对的材料：真实页面 + 真实数据 + 真字体，落在本地 `ui_audit/v11/`（25 张：书库 4 档视口 + 深色 + 青瓷 + 墨绿，详情 / 阅读器（沉浸 + 唤出两态）/ 同步 / 设置 / 批量导入 / 云端书库 / 引导各 1440+390）。

该渲染 harness 属**一次性验证基建，不入库**（`ui_audit/` 与字体派生目录均已 gitignore），本节只留排障经验以免后人重踩：

1. 金测默认字体是 Ahem，所有文字渲染成方块——必须 `FontLoader` 加载真字体。
2. **引擎按字体内部的 family 名分组**，注册名与内部名不一致时该族视为空 → 需用 fontTools 改写 name 表。
3. `msyh.ttc` / `msyhbd.ttc`（字体集合）加载「成功」但取不到字形；单面 `.ttf` 正常。
4. Material 的 `englishLike` typography 默认 `fontFamily: 'Roboto'`；直接写裸 `TextStyle`（如 `AppBarTheme.titleTextStyle`、裸字阶）会**丢掉**这个字体族，文字落到别的字体——这正是本轮修掉的 AppBar 标题与字阶字体不一致问题（见 §9.2 第 13-14 条）。
5. 截图环境没有系统字体回退链，`fontFamily: null` 的文本拿不到 CJK 字形（.notdef 空心框）；真机无此问题。
