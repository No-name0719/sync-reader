# 10 · 界面重设计方案（v1.0.0 之后）

> 状态：**已实施（2026-10-29，v1.1 开发完成；2026-11-03 追加 v1.2 阅读页重设计 A23–A28，见 §9.5）**。实现与原型/决策的出入统一记在 §9 实施记录；`ui_prototype/` 原型保留作设计依据，不再随实现演进（阅读页原型 `reader.html` 为 v1.2 依据）。
> 目标：把 SyncReader 从「能用」提升到「愿意每天用」——书库要像书架，阅读器要像书，同步要像后台而不是噪音。

- 危险操作（清除凭据、删除）与常规项混在同一列表，无视觉分区。

## 2. 设计目标

1. **书库像书架**：一眼看完「有多少本、读到哪、哪些没同步」，而不是「一堆文件」。
2. **阅读器像书**：正文是主角，控件是配角，随时可隐去。
3. **同步是后台**：状态常驻可见但不喧哗；异常才升级为提示。
4. **一套令牌，全局一致**：色彩/字阶/间距/圆角全部集中定义，Flutter 侧落地为 `ThemeExtension`。
5. **跨端自适应**：桌面宽屏用左栏 + 多列；窄窗收成图标栏；移动端改底部标签栏。

## 3. 设计系统

完整可视化见原型「设计规范」页（`ui_prototype/index.html` → 顶部「设计规范」）。

### 3.1 色彩

中性色**带暖调**（纸感），品牌色沿用 teal 但加深降饱和，摆脱 `colorSchemeSeed: Colors.teal` 的塑料感。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#F6F5F1` | `#121317` | 应用底色 |
| `--surface` | `#FFFFFF` | `#1A1C21` | 卡片 |
| `--surface-2` | `#FAF9F6` | `#212429` | 次级填充 |
| `--border` | `#E4E2DB` | `#2C3038` | 1px 描边 |
| `--text` | `#1D1C1A` | `#E9E7E2` | 主文字 |
| `--text-2` | `#6A6862` | `#9EA2AB` | 次要文字 |
| `--success/--warn/--danger` | `#1F7A4D` / `#A95B06` / `#B42318` | 对应提亮版 | 状态语义 |

**品牌风格（accent）可切换**，默认**赭石**（纸墨暖调），用户可在「设置 → 外观」中改。

| 风格 | 浅色主色 | 深色主色 | 气质 |
| --- | --- | --- | --- |
| **赭石（默认）** | `#B25430` | `#E08A62` | 纸墨暖调，贴「读书」这件事 |
| 青瓷 | `#0E7A6E` | `#35B8A3` | 清冷沉静（原 teal 基因，去饱和） |
| 墨绿 | `#2F5D4F` | `#6FBB9F` | 线装书气质 |

每套 accent 含 5 个变量：`--brand` / `--brand-hover` / `--brand-soft`（选中底色）/ `--brand-soft-2` / `--brand-text`（软底上的可读文字色）。
Flutter 侧落为一个 `AppAccent` 枚举 + `ThemeExtension`，持久化到新增的 `app_settings` 表（只增不删迁移）。

**阅读主题独立于应用主题**（可在阅读器内单独切换）：

| 主题 | 背景 | 正文 | 说明 |
| --- | --- | --- | --- |
| 纸白 | `#FFFFFF` | `#26251F` | 默认 |
| 米黄 | `#F6EFE0` | `#40382B` | 旧版「纸张」的升级 |
| 护眼 | `#E5EEE2` | `#2B3529` | **新增**，淡绿护眼 |
| 夜间 | `#14151A` | `#C8CACD` | 比旧版 `#121212` 更柔和 |

### 3.2 字体

**不打包中文字体**（体积代价 17–25MB，与 NFR-04 体积门冲突），全部走系统字体栈：

- **UI**：**按平台解析**（`AppFonts.ui` + `AppFonts.uiFallback`，实现见 §9.20）——
  Win `Segoe UI` + CJK `Microsoft YaHei UI`/`Microsoft YaHei`；Android `Roboto` +
  CJK `Noto Sans SC`/`Noto Sans CJK SC`；macOS/iOS `Helvetica Neue` + CJK
  `PingFang SC`；Linux `Noto Sans` + CJK `Noto Sans CJK SC`/`WenQuanYi Zen Hei`。
  CJK **必须显式列回退族**——不列就交给引擎的系统回退链，落到哪支字体各机器
  不同（Windows 上曾落到一支细体几何黑体，中英像两种字体）。
- **阅读正文**：`Noto Serif SC` / `Source Han Serif SC` / `Songti SC` / `SimSun` → 宋体阅读感。
- **可选第三档**：`KaiTi` / `STKaiti` 楷体。

字阶（UI 基准 14px）：

| 名称 | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| display | 30/38 | 680 | 书名、页面主标题 |
| h1 | 22/30 | 620 | 章节标题 |
| h2 | 18/26 | 650 | 页面标题、卡片标题 |
| h3 | 15/22 | 620 | 分组标题 |
| body | 14/22 | 400 | 正文、列表主行 |
| sm | 13/20 | 400 | 次级正文 |
| caption | 12/18 | 400 | 辅助说明 |
| micro | 11/16 | 600 | 标签、角标 |

**旧版 9px/10px 角标全部上调到 11px 以上。**

### 3.3 间距与圆角

- 间距 4px 基准：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。
- 圆角：`6`（chip）/ `10`（按钮、封面）/ `14`（卡片）/ `20`（大面板）。
- 阴影：三级极浅投影（`0 1px 2px` → `0 14px 36px`），层级主要靠表面色差 + 1px 描边。

## 4. 页面方案

### 4.1 应用外壳（新增）

- **桌面 ≥1180px**：左侧导航栏 232px（品牌区 / **书库 · 同步 · 设置** / 底部同步状态胶囊）。
- **窄窗 1180px 以下**：导航栏收成 68px 图标栏。
- **移动 ≤860px**：隐藏侧栏，改底部标签栏（书库 / 同步 / 设置）。
- 顶栏统一：页面标题 + 副标题 + 右侧动作区，1px 底边线。
- **导航只保留三项**：「工具」分组与工具索引页取消（见 §4.8）。原先散在工具组里的功能重新安置：
  - 导入 → 回到书库顶栏（分裂按钮）；
  - 未上传的书 → 同步页的「未上传的书」卡片；
  - 云端书库管理 → 同步页的「云端书库」入口 → 独立页。

### 4.2 书库

#### 两层筛选（取交集）

筛选拆成**两层**，两层**同时生效、取交集**（不是互斥四选一）：

| 层 | 控件 | 取值 |
| --- | --- | --- |
| 第一层 · 状态 | 常驻 chip 行（互斥单选） | `全部` / `已同步` / `仅本地` / `仅云端` |
| 第二层 · 分组 | 下拉菜单（互斥单选） | `全部分组` / `未分组` / 各分组 / `管理分组…` |

**第一层是四个互斥桶**（云端轴「云端有无」× 本地轴「本地正文有无」组合）：

| 桶 | 定义 | 封面角标 |
| --- | --- | --- |
| `已同步` | 云端有 + 本地有正文 | 阅读百分比 / `待上传` / `同步失败` |
| `仅本地` | 云端没有 + 本地有正文 | `仅本地` |
| `仅云端` | 云端有 + 本地没有正文 | `未下载` |

四态互斥、计数不重叠。**「已删除」的书不在书库里**（删除即移出书库，§4.7b）——`仅云端` 桶只剩真正的云端占位书（其它设备上传、本端还没有正文）。

- **分组不再平铺**：分组数量不可控（用户可自建），平铺成 chip 行会挤爆版面，改为一个下拉。按钮上显示当前选中的分组名（`📂 小说 ▾`）。
- **计数是分面计数（faceted count）**：第一层 chip 上的数字 = 在当前分组筛选下该状态有多少本；第二层下拉里的数字 = 在当前状态筛选下该分组有多少本。两个数字互相联动，用户能提前看到「换一层会剩多少」。
- 右侧灰字给出结果概要：`共 42 本` 或 `匹配 3 / 42 本`。
- 两层交集为空时给出空态（图标 + 说明 + 「清除筛选」按钮），而不是一片空白。
- **旧版的「在读 / 未读」维度被移除**：在读与否是「进度」而不是「状态」，交给右上角「最近阅读」排序表达；混进筛选会让维度语义不清。

#### 书卡交互

- **点封面直接打开书**：书卡上没有任何常驻按钮，也不做 hover 浮层（旧版 hover 出「继续 / ⋯」浮层）。点击封面 = 打开该书（未下载的先触发下载）。
- **信息入口改为手势**：
  - 桌面端 **右键** 书卡 → 弹出上下文菜单；
  - 移动端 / Pad **长按** 书卡 → 弹出同一个上下文菜单。
  - 菜单项：`继续阅读（xx%）` / `下载正文`（未下载时）/ `书籍信息` / `移动到分组…` / —— / `删除本书`（危险色）。
- **封面右上角状态胶囊**（取代旧版封面底部的黑色 `98%` 遮条）：
  - 已下载且在读 → **阅读百分比**（品牌色胶囊，如 `62%`）；
  - 未下载 → `未下载`（墨色胶囊）；
  - 本地已删除 → `已删除`；
  - 同步异常 → `待上传`（琥珀）/ `同步失败`（红）。
  - 卡片下方的文字行只留「⏱ 阅读时长」，百分比不再重复。
- **手势冲突（需注意）**：FR-107 现有「长按拖拽归组」与「长按出菜单」在触屏上冲突。
  **方案**：桌面端保留拖拽归组 + 右键菜单；触屏端取消拖拽归组，统一走菜单里的「移动到分组…」。

#### 其它

- 筛选从弹层改为常驻可见（旧版「全部 ▾」弹层），解决 I2。
- **生成封面改「纸底墨字」**：无真封面（txt / 部分 epub）时，不再用高饱和色块，改为**极低饱和的纸底 + 同色系深墨首字 + 内框线 + 标题/作者排版 + 品牌色小横线**。底色/墨色/框线由内容哈希取同一色相（饱和度 12%、亮度 90%），既保留每本书的辨识度，又不与赭石品牌打架。
- **网格**：卡宽 154px 起（`auto-fill minmax(154px,1fr)`），封面圆角 10px + 轻投影；hover 上浮 3px 并浮出「继续 / ⋯」操作条。
- **进度**：从封面底部的黑色 `98%` 遮条改为**封面下沿 3px 品牌色进度条**。
- **列表模式**：行高 78px，右侧 120px 线性进度 + 百分比；移动端隐藏进度条只留百分比。
- **状态角标**：`仅云端` / `待上传` / `同步失败` 统一为封面左上角胶囊（11px）。
- **同步状态条从内容区移出**，收进左下角胶囊；仅在配额超限/同步失败时，内容区顶部才插入提示条。解决 I1。
- **搜索框**在桌面进顶栏、在移动端落进内容区。

#### 导入（兼容单文件与批量）

- 顶栏导入按钮改为**分裂按钮**：主区「＋ 导入」= 导入文件；箭头展开「导入文件… / 批量导入（文件夹）」。单文件与批量两条路径在同一个入口下，不再散落在「更多」菜单里。
- **导入确认弹窗**（两条路径共用）：文件清单 + 「**同时上传到云端**」勾选（**默认勾选**）+ 上行流量预估（`预计上行 42.6 MB · 坚果云免费额度 1 GB / 月`）。取消勾选时提示切换为「不上传：不消耗上行流量，其它设备看不到这几本书」。
- 取消勾选导入的书标记为「仅本地」，封面右上角显示「仅本地」角标。

### 4.3 书籍详情

- Hero：大封面 168px + 阴影，右侧标题（display 30px）/ 作者 / 标签 / **进度条 + 「62% · 第 128 章」** / 主操作按钮组。
- 「阅读数据」卡片：4 个统计块 + 近 7 天阅读量柱状图。
- 「文件信息」卡片：定义列表（文件名/大小/哈希/添加时间/同步根）。
- 「目录」卡片：**新增目录预览**（旧版只给章数，目录完全在阅读页内）。

### 4.4 阅读器（改动最大；v1.2 阅读页重设计后重写）

> v1.2（阅读页重设计，A23–A28/Q22–Q25，依据原型 `ui_prototype/reader.html`）
> 对本节逐条重写；与原型实现细节的差异统一记在 §9.5。v1.1 版本的描述
> （沉浸态/热区/默认分页等）继续有效，此处不再重复。

- **整行分页（A23，本代阅读器的地基）**：txt 分页内核重写——先用
  `TextPainter.computeLineMetrics()` 量出每行的行盒边界与行首字符偏移，
  再**在行与行之间下刀**：任何一页的行要么整行可见、要么完全不可见，
  页尾不足一行时留白、绝不切字（消灭 v1.0「字符区间二分」的半行问题）。
  每页行数恒定 → 页底留白恒定，上下留白不随内容长短跳动。
- **阅读背景 7 套（A24）**：白色 / 米黄 / 浅绿 / 浅灰蓝 / 深灰 / 深棕 / 纯黑。
  枚举名保持 v1.1 稳定（持久化兼容），展示名改朴素颜色描述；色值权威源
  仍为 `design_tokens.dart` 的 `ReaderPalette`。对比度按 WCAG 2.1 实算
  锁门：正文 ≥7:1（AAA）、次级 ≥4.5:1（AA）。
- **夜间亮度（A25）**：80%–130% 的整屏亮度系数（背景与正文一起变暗/变亮），
  只在夜间系背景（深灰/深棕/纯黑）出现；80% 下限保证正文对比度仍达 AAA。
- **排版面板（A26）**：入口图标由 Aa 改为**齿轮**；新增段距（紧/空一行/
  空两行，以整行为单位）、首行缩进开关（2em ↔ 不缩进）、夜间亮度（A25）、
  翻页动画（A27）四项；面板顶部实时预览跟随全部设置项，预览下方是
  **实时对比度读数**（WCAG 2.1 相对亮度实算，非写死数字）。
- **翻页动画（A27）**：**上下滑动为默认**（正文像滚动一样纵向推移），
  另支持左右翻页；Flutter 侧用 `PageView` 的轴向切换原生实现，分页/滚动
  两模式与翻页路径（热区/音量键）共用同一 `ReaderController`。
- **沉浸态与文字优先（A28）**：进场全隐（Q10 保留）、点空白唤出/收起；
  中区热区点击前先问渲染器「该点是否落在正文文字上」（txt 为字形盒粒度、
  epub/md 为块盒粒度）——点在文字上不切换控件，只有空白处响应。
  **移动端例外（v1.3）**：窄视口（≤460）改为「**点屏幕任意处唤出/收起
  控制条，翻页交给滑动**」——手机屏几乎被正文铺满（正文列 363 逻辑 px ≈

### 4.7b 删除语义变更（本地删除不再保留正文）

**这是对 FR-408 / docs/04 §7.1.2 的一处需求变更，实施时必须同步改基线文档。**

> **2026-11-18 再变更（用户实测反馈）**：v1.1 的「删正文、留元数据」让本地删除
> 的书以「未下载」残影**永久留在书库里**——云端和本地都删掉的书也一样
> （用户实测：「从云端和本地都删除的书籍还是会在书库中出现」）。且同一语义
> 在两端表现不一致：别的设备删的书在本机**消失**，本机删的书在本机**留着**。
> 本节据此把「本地 `books` 行」改回**删除**（移出书库），并作废 v1.1 的
> 「已删除 = 未下载」约定（见 Q21）。

| | docs/04 §7.1.2 原状 | v1.1 变更后 | **现行（2026-11-18）** |
| --- | --- | --- | --- |
| 本地 `books` 行 | 删除（移出书库视图） | 保留（`localPath` 置 NULL） | **删除（移出书库）** |
| 本地正文文件 | 移入应用内「游离文件」区（不删盘） | 直接删除（真正删盘，释放磁盘） | 不变 |
| 封面文件 | 保留在游离区 | 随正文一并删除 | 不变 |
| 进度行 | 随 `books` 行级联清除 | 保留（books 行不删） | **随 `books` 行级联清除** |
| tombstone | 写 `deleted_books` + 推云端 | 不变 | 不变 |
| 云端正文 | 永不删除 | 不变 | 不变 |
| 其它设备收到 tombstone | 正文保留为游离文件 | 不变 | 不变 |
| 该书在书库中的呈现 | 从书库消失 | 保留在书库里，落在「未下载」区 | **从书库消失** |

**为什么改（两轮）**：

- v1.1 改「留元数据」的理由是：`books` 表不允许加列，无法用「新列标记本地已删除」
  区分「仅云端占位书」和「本地已删除书」，于是让两者都落进「未下载」区。
- **2026-11-18 改回「删行」的理由**：① 用户实测——云端 + 本地都删掉的书仍留在书库
  里（残影永久显示，且文档里说的「90 天 GC 后消失」从未发生——GC 只清账本，
  没人删那行）；② 语义不一致比「占位书 vs 已删除书难以区分」更伤——同一个
  删除动作，在别的设备上消失、在本机留着，用户无法建立稳定心智模型；
  ③ 墓碑账本（`deleted_books`）已经把「已删除」这个状态**记在数据层**，
  书库视图不需要（也不应该）再靠一条残行去表达它。

**实施要点（三个必须改的地方，缺一个就会出问题）**：

1. `BooksDao.deleteBook()`：**删 `books` 行**（进度 / 按天阅读时长随之级联清除）
   + 删除正文/封面文件 + 写 `deleted_books` 墓碑 + 清「仅本地」标记（书没了
   标记也失效，否则「未上传的书」计数虚高）。
2. `DriftLocalibrary.listBooks()`：**排除**在 `deleted_books` 里有墓碑的书。
   本地删除已移出书库（无 `books` 行），这里再排除一次是**兜底**：防止
   「墓碑已记账但行仍在」的竞态下被引擎当正常书推回云端，与墓碑打架。
3. `DriftLocalLibrary.applyRemoteMeta(tombstone)`：**本端已发起的墓碑要幂等**——
   若 `deleted_books` 已有该 bookId 的记录（= 本端自己删的），再次收到该
   tombstone 时**不要覆盖**已有的 `deletedAt` / `pushed` / `contentHash`
   （`pushed=false` 是「待推墓碑」的记账，覆盖成 true 会让离线删除的墓碑
   永远推不出去）。本端未发起的（其它设备删的）删行 + 正文转游离区。

**墓碑推送不受影响**：本地行已删时，引擎从 `sync_state` 的上次同步副本
（公共祖先）取墓碑内容照常推送（docs/04 §7.1 规则 1）。

**UI 上不区分「已删除」与「未下载」** → **本条作废**：现在书库里**没有**已删除
的书，「未下载」区只剩真正的云端占位书（其它设备上传、本端还没有正文）。

**重新下载一本已删除的书**：不再有「书库里点下载正文」这条路——删除即移出
书库。云端正文仍在（永不删除），但云端 meta 已变墓碑，本端不再展示它；
需要找回只能重新导入本地文件（会得到一个新的 bookId）。

**删除确认弹窗文案**（现行）：

> 删除后的行为：
> · 本书会从书库移除（阅读进度一并清除）；
> · 本地正文文件立即删除（释放磁盘空间，不可恢复）；
> · 删除标记会同步到云端，其他设备的此书也会从书库移除（它们的正文文件仍保留）。
>
> 不会删除你磁盘上的原始书籍文件。

### 4.7c 「仅本地 / 未上传」状态（新增概念）

**定义**：一本书**本地有正文、云端没有**，且本端**不会自动把它传上去**。
统一的心智模型：**「这台设备自己导入过一次，但没有上传」**。

**两种来源，用户看到的是同一个状态**：

| 来源 | 产生方式 | 内部状态 |
| --- | --- | --- |
| 导入时选「不上传」 | 导入弹窗取消勾选「同时上传到云端」 | 本地标记为仅本地（`local_only_books`），同步引擎完全看不见它 |
| 「从云端移除」后 | 云端管理里把书从云端删掉 | 云端 meta 已删且**不写 tombstone**；本端因仍有 `baseRev`，diff 落到**第 7b 行「云端缺失」→ 保留本地、不删不推** |

两种来源的反向操作都是「**上传到云端**」，恢复成正常同步的书。

**书库里的表现**：封面右上角「仅本地」角标；右键菜单有「上传到云端」/「设为仅本地」。

**同步页的「未上传的书」卡片**列出两类：
1. **仅本地的书**（有书目行）→ 上传 = 解除仅本地标记 → 下次同步走 diff 第 7a 行「本端新书上架」→ 推 meta + 传正文；
2. **游离文件**（只有正文文件、书目行已随删除消失）→ 上传 = 按 `contentHash` 重新关联回书库（FR-408 既有挂回逻辑）+ 上架。

**实施要点**：

1. **新增本地表 `local_only_books(bookId)`**。`books` 表不允许加列（docs/05 §5 DDL 是同步语义的一部分），但有 `book_groups` 这个「纯本地、不同步」的先例，同样处理。需同步更新 docs/05 §5 与 `schemaVersion` 迁移。
2. `DriftLocalLibrary.listBooks()`：**必须排除**仅本地的书 → 它们永不进 diff → 既不推 meta 也不传正文。
3. `pushBookMeta()`：**必须跳过**仅本地的书 → 读进度时也不能把它顺手推上云（进度防抖路径 docs/04 §3 触发时机 3）。
4. 「上传到云端」= 删掉 `local_only_books` 行 + 触发一次全量同步 → diff 第 7a 行 → 上架 meta + 正文。
5. 「从云端移除」= 调 `BackendAdapter.deleteMeta(bookId)`（**不是** `deleteBook()`——后者是推 tombstone 的全局删除）。后端已有 `listMetas()` 与 `deleteMeta()` 两个能力（`backend_adapter.dart`），正好够用，无需新增适配器接口。
6. **副作用要写进文档**：从云端移除后，本端这本书落到 diff 第 7b 行，不会自动再上传；要恢复需「重新上架」（清掉 `sync_state` 的 `baseRev`）。

### 4.8 云端书库管理（新增页面，取代原「工具」三屏）

原「工具」分组（批量导入 / 游离文件管理 / 云端孤儿清理）与工具索引页**整体取消**，功能重新安置：导入回到书库、游离文件并入同步页的「未上传的书」、云端孤儿清理删除。新增**云端书库管理**页。

- 工具索引页 → 删除（导航只留三项）。

**批量导入页保留**，入口改为书库顶栏分裂按钮（§4.2）。

### 9.2 与原型/决策记录的实现出入（按批交付记录汇总）

1. **txt 两端对齐（A10）**：核查确认 Flutter 3.47 的 `TextPainter`/`Text` 引擎级支持 `TextAlign.justify`（作用于软换行行，段末行左对齐——正是中文行为），txt 分页器按整块测量且测量/渲染同参数，故 **txt 实现了真两端对齐**，未降级。
2. **首行缩进**：Flutter 无 `text-indent`，三格式统一用 2 个全角空格（U+3000）前置实现（只动显示层，locator 坐标不变）；epub 走 `<div style="text-align: justify">`（fwfh 不支持 text-indent）。

### 9.4 逐屏比对材料（本地，不入库）

窗口实时截帧在本机开发会话不可用（Impeller 合成限制，客户端白屏——属截帧工具链问题，应用本体渲染正常），故改用**金测渲染**产出逐屏 PNG 作为与原型比对的材料：真实页面 + 真实数据 + 真字体，落在本地 `ui_audit/v11/`（25 张：书库 4 档视口 + 深色 + 青瓷 + 墨绿，详情 / 阅读器（沉浸 + 唤出两态）/ 同步 / 设置 / 批量导入 / 云端书库 / 引导各 1440+390）。

该渲染 harness 属**一次性验证基建，不入库**（`ui_audit/` 与字体派生目录均已 gitignore），本节只留排障经验以免后人重踩：

1. 金测默认字体是 Ahem，所有文字渲染成方块——必须 `FontLoader` 加载真字体。
2. **引擎按字体内部的 family 名分组**，注册名与内部名不一致时该族视为空 → 需用 fontTools 改写 name 表。
3. `msyh.ttc` / `msyhbd.ttc`（字体集合）加载「成功」但取不到字形；单面 `.ttf` 正常。
4. Material 的 `englishLike` typography 默认 `fontFamily: 'Roboto'`；直接写裸 `TextStyle`（如 `AppBarTheme.titleTextStyle`、裸字阶）会**丢掉**这个字体族，文字落到别的字体——这正是本轮修掉的 AppBar 标题与字阶字体不一致问题（见 §9.2 第 13-14 条）。
5. 截图环境没有系统字体回退链，`fontFamily: null` 的文本拿不到 CJK 字形（.notdef 空心框）；真机无此问题。

#### 9.5.2 原型与真实实现的差异清单（本轮交付重点）

1. **分页手段**：原型用 `translateY` + `clip-path: inset()` 在正文坐标系裁切、按「行高取整的槽位」切页；Flutter 侧没有等价的「正文自身坐标系裁切」，改为 **TextPainter 量出的真实行盒边界 + 行首偏移映射**下刀。槽位只是原型的实现副产物——量出的行边界天然落在同一网格上（`TextStyle.height` 使全章行高一致），效果等价而手段不同。
2. **尾随换行的空行盒**：Flutter 引擎会给以 `\n` 结尾的文本排出一个不可见空行盒（`'a\n'` = 2 行），原型（浏览器）没有这个行为——页界落在段首时页尾会凭空多一行。渲染侧用 `txtPageDisplayText` 剥掉属于分页符的行终止符，页高恰为整行数。
3. **视口宽度 < 2em 的病态输入**：缩进自身跨行时整行性不成立，分页退化为「至少推进 1 字符」保底（不丢内容、必然终止）。原型浏览器无此边界（CSS 会悬挂空格）。已在分页器文档与测试注明，48px（3 字宽）以上整行性成立。
4. **夜间亮度下限 70%→80%**：原型的 70% 会把正文对比度压到 ~5.8:1（跌破 AAA）；下限抬高到 80% 并实算锁定（Q23）。作用域同为**整屏**（原型 `filter: brightness()` 在 `.rd` 上，含控制条；Flutter 侧套在阅读页 body Stack 上——抽屉/排版面板是路由层浮层，不参与滤镜，观感一致）。
5. **视觉数值不照抄**：原型的 16px 字号/24px 边距是 Web 观感取值，Flutter 端维持 v1.1 既有的 19px/1.95/16（docs/10 §4.4 v1.1 拍板值）；7 套主题色值按 Flutter 端对比度门自算（如夜间系 muted 提亮到 80% 亮度下仍 ≥4.5:1），不照抄原型 CSS。**（v1.3 改写：经逐项验收与用户确认，字号/页边距改为照原型取 16/24，其余数值仍自算——见 §9.6。）**
6. **翻页动画实现**：原型用两层 div 平移 + `clip-path` 模拟；Flutter 用 `PageView` 轴向切换原生承担（拖拽跟手 + ballistic 均免费），委托翻页（热区/音量键）走 `animateToPage(300ms)`（原型 340ms 就近取整）。**章界差异**：原型全书连排后按章裁切，翻页无「章间隙」；Flutter 沿用 v1.1 的单章 PageView + 首尾「章间页」衔接架构——跨章翻页会先滑入章间页再切换（一次额外推移动画），章内容不会闪出（原型为此要裁剪框的目的已由「每页只渲染本页内容」天然满足）。
7. **「点空白显隐」的命中判定**：原型用行内盒矩形 + 4px 余量遍历判定；txt 用 RenderParagraph 的 `getPositionForOffset` + 单字符字形盒做 **O(1)** 判定（行为等价：点在字形 ±4px 内算文字）；epub/md 因 fwfh/MarkdownBody 不暴露块内字形盒，降为**块盒粒度**（块尾距留白判为空白，可唤出控件）。
8. **正文选择（可选中/长按）**：原型靠浏览器原生选择。Flutter 侧本轮未把正文换成 `SelectableText`（与分页渲染/热区手势竞技场的耦合需要单独一轮验证），点击正文为无操作——「文字优先」的行为要求（点文字不触发控件）已完整交付，选择交互留待后续。
9. **目录小节与「本页 N 行/剩余约 N 分钟」**：原型的二级小节是假数据（txt 无小节信息），目录层级仅对 epub/md 有意义（`TocEntry.level` 既有），txt 保持扁平；「本页 N 行」与剩余分钟原型是自造估算，**未做**——按提示词要求复用 `progress_anchor`/locator 机制，留待 P1。
10. **盘古之白**（中西文加空隙）：原型在显示层包 span 实现；Flutter 侧同样应走显示层文本变换且不破坏 locator 坐标——本轮未做（P1，插入点表基建已就绪，扩展成本可控）。
11. **目录里各章页数**：P1 未做；若做，页数来源须为分页结果（分页器已能给出，UI 未接）。
12. **epub/md 分页现状（如实标注）**：epub page 模式保持 v1.1 的连续排版 + 视口高度吸附（docs/07-R2 登记方案；fwfh 块化 HTML 无法在 isolate 预测量行盒，整行分页需另起渲染架构）；md 的 page 模式仍按 scroll 呈现。二者的现状已在排版面板「翻页方式」说明文字**如实标注**（「滚动 = 上下滑动连续阅读；分页 = 一页一页翻（epub 按屏吸附；md 暂按滚动；pdf 按文件自带页）」），不假装支持。pdf 渲染路径未动。
13. **对比度数字**：原型标注的是 Web CSS 色值的计算结果；Flutter 侧读数为 `design_tokens` 权威色值的 WCAG 2.1 **实算**（面板显示 + 测试锁定），不是写死数字。
14. **夜间亮度/段距/缩进/翻页动画的持久化**：JSON schema v2→v3（只增不删：新增键缺省回落默认；主题名读取规则 v≥2 一致），`ReaderTheme` 枚举名未动——旧 `reader_settings` 数据零迁移成本。

### 9.7 实施记录（v1.3.1 阅读翻页修复，2026-11-16）

用户实测（Windows 桌面端，epub 小说 + 内嵌插图）报了两条：**① 上下键翻页「按下后一直翻页停不下来」，且大多翻到下一张图；② 插图与上下文字挤在一页、或被切成两页各露一半（图片重复两次）**，要求「插图单独一页」。两条都指向 9.6 之后那轮「页界停行边界 + 插图整页槽」的改动（commit `1267930`），根因与修法如下。

**根因**

| 现象 | 根因 |
| --- | --- |
| 按住方向键狂翻页 | 阅读页把 `KeyRepeatEvent`（系统自动重复）也当成翻页键：按住不放时系统连发重复事件，逐个翻页 → 一屏内翻过几十页，插图页夹在中间根本停不住 |
| 一按就跳到下一张图 | 插图块只登记了**块顶**一个页停候选 → 「一屏之内出现插图就把页终点落在插图顶」这条规则使正文页提前结束，正文页翻页直接落到插图顶 |
| 插图与下方文字同页 | 插图块底**不是**页停候选 → 插图页的终点是插图之后的第一个行边界 → 插图与它下面那行文字同页 |
| 插图被切成两页 | 页界可能落进插图内部（插图不是原子单位）→ 上下两页各露一半，看起来「图片重复两次」 |
| 一次按键翻两页 / 退不回去 | 翻页落点（`jumpTo`）末尾会触发一次 `goBallistic(0)`，弹道物理按「就近页停」再吸附一次；页停关系不唯一（多个行边界都指向同一插图顶），就近吸附会落到**另一页** → 一次按键翻两页、且回退键退不回去 |

**修法**（新增 `epub_page_structure.dart`，纯 Dart、可单测）

- **页停候选升级为「页起点」**：文本行 = 行盒顶的安全落点；**插图块 = 原子区间 [块顶, 块底]**（块顶与块底都是页起点）→ 页界绝不落在插图内部，插图天然独占一页。
- **页结构规则**：文本页终点 = 一屏之内最靠下的行边界（页尾留白不足一行）；一屏之内出现插图 → 该页终点 = 插图块顶（插图另起一页）；本页从插图顶起 → 终点 = 插图块底。
- **页起点链**：走过的页起点按序记住 → 前后翻页**精确往返**（下一页 → 上一页回到原落点）；弹道物理与视口裁剪用只读探测（「试算」不写链），避免猜测污染链。
- **候选表整表替换**（不跨滚动累积）：块的排版会随上方内容落定而微移（fwfh 的列表/引用高度会补齐），累积旧坐标会与新坐标打架（同一张插图在表里出现两个块顶，页界就算错）。

### 9.8 实施记录（v1.3.2 性能优化，2026-11-17）

用户实测（Windows 桌面端）报了两条**性能**问题：**① epub page 模式下被页界切断的那一行/图片会「先出现 1–2s，然后移除或展示这一行」（闪一下）；② Windows 点关闭按钮后要 10–20s 页面才关闭**。两条都要求「用户无感 / 立即」，且排查要有实测证据。

#### 9.8.1 epub 页尾闪烁（1A）

**根因（实测定位，非猜测）**

用 widget 测试探针量「**实际生效**的裁剪高度」（`RenderClipRect` 的裁剪矩形 vs 渲染器算出的值）：

| 时机 | 渲染器算出的裁剪高度 | **实际生效**的裁剪高度 |
| --- | --- | --- |
| 首页 | 220.2 | **600.0（= 整屏）** |
| 翻 1 页 | 557.6 | **600.0** |
| 翻 2 页 | 596.5 | **600.0** |
| 翻 3 页 | 571.8 | **600.0** |

即：**裁剪矩形从未生效**，页尾的半行/半图一直露着。原因是框架的 `RenderCustomClip` 会**缓存**裁剪矩形（`_clip ??= clipper.getClip(size)`，见 `flutter/lib/src/rendering/proxy_box.dart:1555`），而自定义 clipper 不会自动通知失效 → 裁剪矩形一直停在**首帧**算出的值（首帧还没有行盒，多半是整屏）。叠加第二个坑：页终点测量放在**帧末**（post-frame），画这一帧时用的是上一帧的旧落点 → 翻页瞬间先露半行、下一帧收紧 → 「闪一下」。

**修法**

- **裁剪矩形每帧现算**：page 模式视口从 `ClipRect(clipper:)` 换成自绘视口 `_EpubPageViewport`（`RenderProxyBox` 子类），在**绘制阶段**算裁剪高度并施加裁剪 → 不再受框架的裁剪矩形缓存影响。
- **候选未知时取保守值，绝不退化成「不裁剪」**：`pageContentHeight` 的取值顺序 = ①页终点（行边界/插图边界）→ ②视口内最后一条**安全边界**（行落点/插图块顶底/无行盒块的块底）→ ③内容到此为止（文档末尾）→ ④**留白 0**。宁可页尾多留白（裁得更早），也不让页界落在行中间（切字）。
- **候选与「已测量内容」绑定（代次失效）**：`EpubPageStructure` 增 `epoch`（排版代次）+ `safeBounds`（安全边界）+ `largestSafeWithin`（保守裁剪查询）；几何变化（字号/行高/页边距/字体/翻页模式）→ 代次自增 → 旧候选与旧页起点链一并作废（新旧坐标不混在一张表里）。
- **行盒缓存失效条件收紧**：`_EpubBlockLines.matches` 原先**只比尺寸** → 内容/样式变了但尺寸恰好没变时会命中过期行盒；改为同时比对**排版代次 + 样式指纹**（字号/行高/字体/页边距）。
- **拖动中不再整屏放开**：旧实现 `_userScrolling` 时整屏不裁剪（拖动会看到半行）；现在拖动同样按安全边界收口。

**回归**：新增 `epub_page_clip_test.dart`（7 例）：
①**像素级**断言「裁剪线以下页尾无半个字形」（截 `RepaintBoundary` 逐像素数非背景像素 → 裁剪失效时必红）；②裁剪线必须落在行边界（无行盒横跨）；③翻页**中间态**（跳后尚未出帧）裁剪高度不得等于整屏；④页结构的保守裁剪查询 / 代次失效 / 整表替换（纯 Dart 单测）。app **850 测试全绿**、`flutter analyze` 零告警。

#### 9.8.2 Windows 关闭窗口要 10–20s（1B）

**根因（实测定位）**

`scripts/drive_app.ps1` 新增 `Close` 动作（发 `WM_CLOSE` → 轮询窗口何时消失 → 再等进程退出），配合应用内临时打点，实测：

| 阶段 | 耗时 |
| --- | --- |
| Dart 侧 `onWindowClose` 进入 → `_save()` 完成 | **16ms** |
| `windowManager.destroy()` 返回 | **17ms**（即 Dart 侧全程 17ms） |
| 心跳（1s 一次） | `destroy()` 之后**立刻停止**（Dart 侧已收工） |
| **窗口真正消失** | **12,014ms** |
| **进程退出** | **12,111ms** |

即：Dart 侧 17ms 就干完了，卡住的是**原生窗口**——`window_manager` 0.5.2 在 Windows 上的 `destroy` 只发 `PostQuitMessage(0)`、**不销毁窗口**（`windows/window_manager.cpp:232`），而 `setPreventClose(true)` 又让插件拦下 `WM_CLOSE`（`windows/window_manager_plugin.cpp:319`）→ 窗口一直挂在桌面上，直到引擎收尾才消失（实测 11–14s，与用户说的 10–20s 吻合）。

**修法**：关闭序列改为「**先落盘 → 解除 preventClose → 原生关窗**」（`windowManager.close()` = `WM_SYSCOMMAND/SC_CLOSE`），不再用 `destroy()`；落盘失败也照常关窗（只记日志），并防重入（原生关窗会再触发一次 `WM_CLOSE`）。

**实测对比**（同一台机器、同一脚本）：

| 关闭方式 | 窗口消失 | 进程退出 |
| --- | --- | --- |
| 旧：`destroy()` | 12,014ms | 12,111ms |
| 新：`setPreventClose(false)` + `close()` | **133ms** | **258ms** |

**回归**：新增 `test/app/window_close_test.dart`（3 例）：关闭序列顺序（落盘 → 解除阻止 → 关窗）、落盘失败也要关窗且要上报、关窗异常不吞。`scripts/drive_app.ps1` 增 `Close` 动作（关闭耗时实测工具）。


### 9.9 实施记录（v1.3.3 目录跳转与新章节另起一页，2026-11-17）

用户实测反馈：**「偶尔通过章节选择跳转时会出现上一次提交修复的连续翻页问题，且通过翻页方式到新的章节时没有新起一页」**。两条都指向 epub page 模式的页结构（9.7 引入的「页起点 + 页起点链」）。

#### 9.9.1 目录跳转后「连续翻页」（2A）

**根因（实测定位，非猜测）**

写探针跑真实 epub（page 模式）：先翻 3 页制造一条**旧页起点链**，再从目录跳到第二章，逐帧观察滚动位置：

| 时刻 | 滚动偏移 | 页起点链 |
| --- | --- | --- |
| 跳转前（第 3 页） | 1404.1 | [29.8, 250.0, 807.6, 1404.1] |
| 跳转后第 1 帧 | 865.8 | 同上（**旧链原封不动**） |
| 之后 30 帧内 | 848.5 → 829.6 → 818.6 → 813.0 → 810.2 → **809.1** | 同上 |
| 静置后 | **807.6**（= 旧链里的旧页起点！） | 同上 |
| 逻辑位置 | **spine 0（还在第一章！）** | — |

即：**跳转没有落到第二章，反而被拽回旧页起点 807.6**。两个原因叠加：

1. **弹道仿真与定位循环打架**（主因）：`ScrollController.jumpTo` 末尾必触发 `goBallistic(0)`（`scroll_position_with_single_context.dart:206`）→ 命中自定义物理 `EpubPageScrollPhysics.createBallisticSimulation` → 走 `nearestPageStart`（就近页起点吸附）。而定位循环 `_locatePosition` 正是用一连串 `jumpTo` **逐步逼近**目标块：每一次 `jumpTo` 刚把位置放到目标附近，紧跟着的弹道又把它吸附回**旧链里的旧页起点** → 定位永远收敛不了，页面在旧位置与目标之间来回滑（用户看到的「连续翻页」）。链为空时弹道也会把位置推走一屏（`_targetPixels` 的兜底 `pixels + viewport`），同样与定位循环对着干。
2. **旧页起点链没有作废**（叠加）：目录跳转是「**位置语义断裂**」——新位置与旧位置的页起点**不再相邻**（中间隔着整段没走过的内容）。但 `EpubPageStructure` 的链只在**排版几何变化**（`epoch`）时才清，跳转不改几何 → 旧链原封不动留着 → 弹道吸附专挑旧页起点吸、翻页也沿旧链跳回旧章。

**修法**

- **定位期间不产生弹道仿真**：`EpubPageScrollPhysics.createBallisticSimulation` 开头 `if (renderer._locating) return null;` —— 定位循环自己控制位置，不再叠加弹道吸附。
- **跳转时作废旧页起点链**：`EpubPageStructure.invalidateChain()`（清链），在 `jumpToTocEntry` / `jumpToPercent` / `restore` 三条**位置语义断裂**的路径上调用；随后把**跳转落点登记为新页起点**（`registerPageStart`）——落点成为新一页的锚，前后翻页以它往返。
- **粗跳估计改为「按已构建区外推」**（顺带修掉的定位缺陷）：`_locatePosition` 的粗跳原本按**全书字符比例**换算偏移。字符密度与像素密度在插图页/长短段落下严重失真 → 粗跳落到目标一屏开外 → 目标块构建不出来 → 定位 12 轮不收敛 → **目录跳转落到别的章**。改为按**已构建区的块序号外推**（已构建区高度 ÷ 块数 = 平均块高），每跳一次已构建区随之移动、下一轮估计更准（割线法收敛）。

#### 9.9.2 翻页进入新章节没有另起一页（2B）

**根因**

`EpubPageStructure._successor` 的页终点规则是「一屏之内最靠下的行边界候选」——**页结构不知道章节边界在哪**，于是章边界只是普通内容：上一章的末行与下一章的标题会被排进同一页（实测：第一章末页 807.6 → 1404.1 的一屏里同时装着第一章收尾段落与第二章标题、第二章正文）。

**修法**

- **章边界进页结构**：`EpubPageStructure` 增「章节起点」表（`chapterStarts`，文档坐标）。渲染器实测时把 **spine 首块的块顶**登记为章起点（`_isSpineStart`；首章不算边界——它在文档顶端，否则第一页会变成只有内边距的空页）。
- **页终点不得越过章边界**：`_successor` 在「一屏之内出现下一章节起点」时把页终点压到该章起点；章起点本身即合法页起点 → **新章节另起一页**，章题不被挤在上一页尾部。
- **上一页也不得跨章**：`_predecessor` 的「后继恰为 from」判定改用**未夹章边界**的原始后继（夹了之后一屏内多个候选都映射到同一个章起点，上一页起点会失准），并加**跨章下限**（上一页与本章同章；落点恰是章起点时允许落在上一章）。
- **裁剪跟着走**：视口裁剪高度取「下一页起点 − 视口顶」，页终点即章起点 → 上一章末页页尾留白到章首，章题完整落在下一页顶部。
- 既有契约不破：**插图独占一页**（章边界在插图之后时插图规则优先）、**页界不切字**（章起点 = 块顶，位于章题文字之上，不切任何字形）。
- **txt/md/pdf 无需改动**：txt 本就**逐章分页**（每章独立页表 + 章间页，天然另起一页）；md 的 page 模式按滚动处理（docs/10 §9.5.2 已登记）；pdf 用文档自带页。

**回归**（新增 `epub_toc_jump_test.dart` 6 例 + `epub_page_structure_test.dart` 增 5 例）

| 用例 | 钉死的契约 |
| --- | --- |
| 跳转落到目标章且落点稳定不被弹道拉回 | 跳转真的到位（spine 正确）、推进多帧位置不漂移、旧页起点链已作废 |
| 跳转后按一次 ↓ 只前进一页 | 落点 = 紧邻的下一页起点，且位移 ≤ 一屏（不得连翻） |

| 上一章的末页止于章边界 | 裁剪终点 == 章起点；章题行盒不在上一页可见区内 |
| 逐页翻到第二章时落在章起点 | 翻页进入新章 = 落在章起点 |
| 页结构（纯 Dart）：跳转作废链 / 落点登记 / 章边界夹断 / 上一页不跨章 | 页结构规则单测 |

### 9.10 实施记录（v1.3.4 移动端书架密度，2026-11-17）

用户实测反馈：**「页面调整：移动端书架一屏幕展示 3*3 - 3*4 本书，目前大概仅 2 * 1.5 左右的样子」**。

#### 9.10.1 根因：列数被算了两遍（手机实得 2 列）

改造前的网格把「列数」算了两次：

- 页面里按 `ceil(内容宽 / 176)` 推算卡宽并据此算 `childAspectRatio`；
- `SliverGridDelegateWithMaxCrossAxisExtent(176)` 内部却按 `ceil(内容宽 / (176 + 列间距 16))` 真正排布。

两个口径在手机上不一致（内容宽 358 时前者得 3 列、后者实得 **2 列**），于是：

| 视口 | 内容宽 | 页面手算列数 | 委托实得列数 | 实得卡宽 × 卡高 | 首屏完整可见 |
| --- | --- | --- | --- | --- | --- |
| 360×640 | 328 | 2 | 2 | 156 × 314 | 1 行（2 本） |
| 390×844 | 358 | **3** | **2** | 171 × 377 | 1 行（2 本）+ 半行 |
| 412×915 | 380 | **3** | **2** | 182 × 394 | 1 行（2 本）+ 半行 |
| 430×932 | 398 | 3 | 3 | 122 × 260 | 2 行（6 本） |

实测（改造前，网格视口含应用外壳的顶栏/搜索/筛选/底栏）：390 宽只完整看到 **2 张**卡 + 第三行被切一半 —— 与用户说的「2 * 1.5」完全对上。手算列数与实得列数不一致还带来第二重浪费：宽高比按 119px 的「假卡宽」算，实际卡宽 171px → 每张卡凭空多出约 37px 空白（卡片格子比内容高）。

桌面端两者恰好一致（1240 内容宽 → 7 列；860 → 5 列），所以问题只在窄屏暴露。

#### 9.10.2 修法：唯一度量来源 + 窄屏紧凑卡

**① 度量收敛到一处**（新增 `lib/features/library/library_grid_metrics.dart`，纯 Dart 可单测）

列数 / 卡宽 / 卡高 / 一屏几行由 `computeLibraryGridMetrics()` 一次算出，页面按它设 `SliverGridDelegateWithFixedCrossAxisCount(crossAxisCount: 列数)` 与 `childAspectRatio`，测试按它断言「每行几本 / 一屏几行」——两侧不再各算一套，也不再有「`_gridCardMetaHeight` 与实际卡高不一致」的隐性契约（宽高比改为按**真实卡宽**反推，桌面卡高 315.6 → 322.4px，消除那 37px 幽灵留白）。

**② 按断点分两档**

| 档 | 触发 | 规格 |
| --- | --- | --- |
| 宽屏（`comfortable`） | 视口宽 > 520 | 沿用 v1.1：列数 `ceil(内容宽 / (176+16))`（1440 → 7 列、860 → 5 列、1180 → 6 列）、封面 2:3 + 文字区 84px（书名两行 + 作者 + 时长） |
| 窄屏（`compact`） | 视口宽 ≤ 520（手机竖屏） | 固定 **3 列**、内边距/间距 12、封面 + **书名叠加封面底部**（无文字区）→ 卡高 = 封面高 |

**③ 窄屏封面比例按「一屏至少 3 行完整可见」自适应**

**④ 纸底墨字封面在紧凑卡下关掉自己的文字块**（`CoverView.showTextBlock`），避免书名出现两次（封面排一遍 + 叠加层再排一遍）。

#### 9.11.1 方案选型（A/B/C 对比）

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| **A：独立云端对象集合** | 分组以 `groups/{groupId}.json` 上云（与 `meta/` 平级），每组自带 rev/CAS/LWW；书籍 meta 增可选 `groupId` | 分组与书籍同构，冲突/墓碑/GC 语义统一；改 A 组名与改 B 组名互不冲突；不污染书籍清单与去重逻辑 | 需扩展 BackendAdapter/LocalLibrary/SyncStore 三套接口 | ✅ **采用** |
| B：单个 `groups.json` 集合文件 | 整文件 CAS，文件内每组各自 rev + LWW | 单文件、实现简单 | 并发改不同分组也撞整文件 CAS；文件随分组数增长 | ❌ |
| C：只把 groupId 塞进书籍 meta | 不传分组名/顺序 | 改动最小 | 不满足"B 端看到同样的分组名与排序"（用户核心诉求） | ❌ |

#### 9.11.2 关键设计决定

- **云端目录**：`groups/` 与 `books/` 平级（**不放进 `meta/`**——`meta/` 的
  Depth:1 PROPFIND 用于枚举书籍，混入分组文件会污染清单与哈希去重）。
  `ensureLayout()` 幂等创建，老云端目录首次同步自动补建（不报错）。
- **schema 只增不删**：书籍 meta 增**可选** `groupId`（String?），云端 meta 的
  `schemaVersion` **保持 1 不变**（新增可选字段不构成结构变更；旧客户端读到
  会忽略，写回丢失分组归属 = 降级为"未分组"，已登记 docs/07 R17）。
  分组 meta 是**独立文件类型**，自带 `schemaVersion=1`。
- **同名分组合并**（用户场景"B 端可能已手工建了同名分组「小说」"）：
  按名称聚类 → **规范 id = 簇内字典序最小者**（ULID 时间有序 → 最早创建者
  优先）→ 其余 id 的本地行删除 + 组内书籍 `group_id` 迁移到规范 id；云端冗余
  条目在规范分组确实在云端时删除。规则**对两端对称**（同样的 id 集合在 A/B
  端得到同一规范 id），避免"各把本地那条并入云端那条"的乒乓。
- **阶段顺序**：同名合并 → 书籍 Diff → 拉分组 → 拉书籍 → 推分组 → 推书籍。
  分组先于书籍，保证书籍 meta 的 `groupId` 不指向尚不存在的分组。
- **删除语义**：本地删除分组 = 软删（`book_groups.deleted=1`）+ 组内书
  `group_id` 置 NULL（回未分组，**不丢书**）→ 推分组墓碑
  `groups/{groupId}.json`（`deleted=true`）；其它端收到墓碑即移除该分组。

### 9.12 实施记录（v1.3.5 翻页时滚动条跳变，2026-11-17）

用户实测反馈：「往下翻页时右侧的滚动条会上下挑动，内容是往下翻的」。

#### 9.12.1 根因（实测定位）

框架的桌面滚动条（`MaterialScrollBehavior.buildScrollbar` 在 Windows/macOS/Linux 给纵向滚动视图自动挂 `Scrollbar`）**滑块的长度与位置**来自滚动指标里的 `maxScrollExtent`——而 epub 正文是一个**惰性列表**（`ListView.builder` + 变量高的块）：

- 未构建的块按「原型估高」计入总高；
- 离开惰性窗口被回收的块**退回估高**；
- epub 块高差异极大（整页插图 ≈500px、普通段落 ≈50px）。

于是每翻一页（构建/回收一批块）总高估计就跳变数百像素。实测（widget 探针，逐帧记录）：

| 翻页 | pixels | maxScrollExtent | 滑块起点 | 滑块长度 |
| --- | --- | --- | --- | --- |
| 起始 | 24.0 | 3795.0 | 0.0055 | 0.1365 |
| p0 | 250.0 | 3612.4 | 0.0593 | 0.1424 |
| p1 | 807.6 | 3449.7 | 0.1994 | 0.1482 |
| p2 | 865.8 | 3463.6 | 0.2131 | 0.1477 |
| p3 | 1435.1 | 3037.8 | 0.3945 | 0.1649 |
| p4 | 2012.5 | 3056.0 | 0.5505 | 0.1641 |

像素级复测（Windows 平台真实渲染的滚动条，扫描右侧条带内的滑块像素）：滑块**高度**在 81 / 88 / 98 / 40 px 之间跳、**位置**逐页跳 31 / 84 / 120 / 92 / 77 px —— 即用户看到的「一边变长一边跳位」。

> 注：这不是「翻页动画抖」，而是**翻页后惰性列表重建/回收块 → 总高估计跳变**；翻页本身是瞬时跳转（`jumpTo` + 链命中 → 无弹道仿真），所以内容平滑下移、只有滚动条在抖。

#### 9.12.2 修法

**分页视图（page 模式）不挂框架自动滚动条**（`epub_renderer.dart`）：

```dart
return ScrollConfiguration(
  behavior: ScrollConfiguration.of(context).copyWith(scrollbars: false),
  child: _EpubPageViewport(renderer: r, child: list),
);
```

理由三条：

1. **分页视图里像素级滚动条本就没有意义**——翻页是离散的，拖滚动条也无法定位到"第几页"；阅读位置由阅读器底部的进度轨承载。
2. **与既有分工一致**：txt 分页用 `PageView`（本就无滚动条）、md 滚动用 `ListView`（有滚动条）——本项目既定规则即「分页视图无滚动条、滚动视图有滚动条」。
3. **滚动视图（scroll 模式）保留滚动条**（可拖拽跳转），不误伤。

注意事项：`ScrollBehavior.copyWith` 返回 `_WrappedScrollBehavior`（包一层 delegate，`dragDevices` 等仍由应用自己的 `AppScrollBehavior` 提供），故**桌面鼠标拖拽（v1.3 E5-2）不受影响**；且 `copyWith` 的 `scrollbars` 缺省值是 `true`，必须显式传 `false` 才能关掉。

#### 9.12.3 新增测试与「改坏 → 变红」

新增 `apps/sync_reader/test/reader/epub/epub_scrollbar_test.dart`（3 例，桌面平台 `debugDefaultTargetPlatformOverride = TargetPlatform.windows`）：

1. page 模式：正文视图里**没有** `Scrollbar`；
2. scroll 模式：**仍有** `Scrollbar`；
3. 关滚动条**不得**影响桌面鼠标拖拽（视图内层 `ScrollConfiguration.behavior.dragDevices` 仍含 `PointerDeviceKind.mouse`）。

「改坏 → 变红」实测：去掉 `ScrollConfiguration` 包裹后 → 用例 1 报 `Found 1 widget with type "Scrollbar"`、用例 3 报 `Found 0 widgets with type "ScrollConfiguration"` → 还原后全绿。

#### 9.12.4 遗留风险

- epub **scroll 模式**仍保留滚动条，其总高估计同样会漂移（惰性列表的通病），但连续滚动时变化被平滑滚动掩盖，观感远轻于分页时的"逐页跳变"。
- md / txt 的 scroll 模式同属惰性列表，桌面端存在同类漂移；本次未改（用户反馈聚焦于分页阅读），如需一并处理可按同一原则逐个评估。

2. 「移动端滚动分页直接滑动会一次性滚动很多，需要按住屏幕滑动才能控制」；
3. 「移动端无法切换滚动和分页模式」。

三条**不是三个独立缺陷**：①与③同源（阅读设置的读写链路），②分两处（分页模式的滑动落点 + 滚动模式的甩动惯性）。

#### 9.13.1 根因（实测定位）

**① 与 ③：`ReaderSettingsRepository.load()` 返回首次载入的旧快照**

仓库的 `load()` 把首次载入的 `Future` 记下来并**一直返回那个快照**：

```dart
Future<ReaderSettings>? _loaded;
Future<ReaderSettings> load() => _loaded ??= _doLoad();   // ← 旧实现
```

`save()` 只更新内存缓存 `_cached` 与广播，**不更新这个快照**。于是会话中改过设置后：

- 设置页重新进入 → `_loadReaderDefaults()` → `load()` → 拿到**改之前**的值 → 显示出厂默认（反馈 ①）；
- Aa 排版面板重开 → `initState` 先取 `repo.current`（新值），随后 `load().then(...)` 用**旧快照**把它覆盖回去 → 面板又显示默认（反馈 ①）；
- **换一本书** → 阅读页打开链路 `await _settingsRepo.load()` → 渲染器按**旧快照**创建 → 字号/主题/翻页模式全部回退出厂默认（反馈 ③：切到滚动后换一本书又变回分页，等于"切不动"）。

实测（`ReaderSettingsRepository` 单测）：`save(fontSize: 22)` 之后 `load()` 仍返回 `fontSize: 16`。

**② 之一（epub 分页模式）：弹道落点以「松手时的偏移」为基准**

`EpubPageScrollPhysics._targetPixels` 用 `position.pixels`（松手时的偏移）算落点。而页结构的 `_successor(from)` 假定 `from` **是页起点**（它算的是"从 from 起一屏内的最后一行"）——传入一个页中间的偏移，落点就会**多挪一屏**：

| 滑动 | 松手偏移 | 落点 | 实际位移 |
| --- | --- | --- | --- |
| 一次 260px 甩动 | 284.0 | 1124.3 | **1100px ≈ 1.3 屏**（且落点不是页起点） |

叠加"滑动幅度越大松手位置越靠后"，一次滑动翻的页数随滑动幅度漂移 → 用户只能"按住屏幕慢慢滑"才控得住（反馈 ②）。

**② 之二（滚动模式）：平台默认甩动不封顶**

滚动模式用平台默认物理，手机上一次重甩（8000 px/s）实测位移 **7306px ≈ 12 屏**（400×600 视口）——"一次性滚动很多"。

#### 9.13.2 修法

**① 与 ③：`load()` 返回当前生效值**

```dart
Future<ReaderSettings> load() {
  final pending = _loading;
  if (pending != null) return pending.then((_) => _cached);  // 等首次载入，取当前值
  return _loading = _doLoad();
}
```

- 首次载入完成后一律返回 `_cached`（`save()` 会同步更新它）；
- 首次载入**进行中**发生保存时，以保存值为准（`_saveSeq` 竞态守卫：不以旧库值覆盖新值）；
- Aa 面板与设置页各自订阅仓库的 `changes` 流 → 别处改过设置后，页面实时跟随，不再显示旧值。

**③ 补入口**：设置页「阅读」区新增「默认翻页模式」分段控件（分页 / 滚动）——移动端的 Aa 面板是底部弹层，翻页模式一项埋在面板下半部分不易发现；设置页是移动端最容易到达的入口。

**② 之一（epub 分页模式）：一次滑动 = 一页**

- 视图用 `NotificationListener<ScrollStartNotification>`（`dragDetails != null`）记录**滑动起点**；
- 弹道落点改以**滑动起点所在页**为基准：`peekNextPageStart(base)`（= 下一页起点），而不是"从松手偏移往后一屏"；
- 落点**首次算出即缓存**：弹道飞行途中惰性列表构建/回收块 → 内容尺寸变化 → 框架 `BallisticScrollActivity.applyNewDimensions` 会**重启**弹道，而重启时速度可能为 0（动画还没起步）——若每次重启都重算落点，"无速度"分支会改用"就近页起点" → **落点突变**（实测：页面先被拽到别处、再弹回文档头）；
- 拖拽越过目标页界时，落点会落在当前位置**之前**（内容回退到目标页）→ 此时弹簧速度取 0，否则弹簧带着甩动速度朝反方向冲（实测页面一路弹到文档头）；
- 落位后把目标页起点登记进**页起点链** → 前后翻页仍能精确往返。

实测（同一夹具，手机视口 390×844）：

| 滑动 | 旧实现落点（位移） | 新实现落点（位移） |
| --- | --- | --- |
| 一次 260px 甩动 | 1124.3（1100px ≈ 1.3 屏，落点非页起点） | 250.0（**226px = 下一页起点**） |
| 一次 500px 甩动 | 1109.8（1086px ≈ 1.29 屏） | 250.0（**226px = 下一页起点**，与滑动幅度无关） |

**② 之二（滚动模式）：甩动位移封顶**

新增 `reader_scroll_physics.dart` 的 `ReaderScrollPhysics`：不换仿真模型，只把**甩动速度**封顶——平台自己的抛掷仿真（Android spline 减速 / iOS 回弹）算出的位移自然被限住，手感仍是平台原生的，只是"甩不远"。上限 = 视口高 × 1.2 屏，按 Android 甩动模型反解速度（`d = v · 0.35 · (v / vRef)^0.7364`，`vRef = friction · physicalCoeff / inflexion`，`physicalCoeff` 含平台的 0.84 手感系数）。epub / txt / md 的滚动视图统一挂上。

实测（600px 视口、8000 px/s 重甩）：平台默认物理位移 **7306px ≈ 12 屏**；封顶后 **744px ≈ 1.2 屏**（另加手指自身位移）。

### 9.14 实施记录（v1.3.7 翻页设置合并为一个选项，2026-11-17）

用户实测反馈（附 Aa 面板截图）：「这里只要有滚动（上下）和分页（左右）两种模式就行了，不用切割为翻页模式和翻页动画两个选项」。

#### 9.14.1 问题

设置里有两个控件：

- **翻页模式**：分页 / 滚动
- **翻页动画**：上下滑动 / 左右翻页（仅分页模式出现）

对读者而言这是**同一个选择被拆成两问**：选了"分页"还要再选"上下还是左右"；而且第二个控件**只对 txt 有效**（epub 的分页是"连续排版 + 按屏吸附"，纵向滑动；md 始终滚动；pdf 用文件自带页）——即为一个格式专有的细节占了一个通用入口。

#### 9.14.2 追问：电脑侧还有必要做「上下 / 左右」的区分吗

**没有必要**（用户追问后核实）——电脑上翻页本来就有**三条与方向无关**的路：

| 途径 | 是否受翻页方向影响 |
| --- | --- |
| 点正文左右两侧热区（桌面热区 = 翻页） | 否 |
| 滚轮一格 = 翻一页（渲染器直接接管滚轮，横纵轴都吃纵向分量） | 否 |
| 方向键 ↑/↓/PageUp/PageDown | 否 |
| **鼠标按住拖拽** | **是**（唯一受方向影响的手势，且是次要交互） |

而方向本身**还随格式而异**：txt 手机左右滑 / 电脑上下拖，epub 无论什么设备都是上下滑动按屏吸附——把方向写进选项名必然对某种格式说谎。故：

- 翻页**方向**从「用户选项」降级为「**按设备形态自动选**」：手机（窄视口 ≤460）横轴（翻书手感），电脑纵轴（与滚轮/鼠标拖拽同向，手感不回退）；
- 持久化里的 `pageTurnAxis` **不再被采纳**（旧键只增不删地留在 JSON 里，读回时归一为 `horizontal` 以免旧值残留）；
- 选项文案**不再带方向后缀**（`分页` / `滚动`），方向只在说明文字里逐格式写明。

#### 9.14.3 修法

**合并为一个「翻页方式」**，只有两个选项：

| 选项 | 语义 | 落地 |
| --- | --- | --- |
| **滚动** | 上下滑动连续阅读 | `pageMode = scroll`（epub/txt/md 均支持） |
| **分页** | 一页一页翻 | `pageMode = page`（方向按设备形态自动选） |

- Aa 面板：删掉「翻页动画」整块，「翻页模式」改名「翻页方式」，选项文案 `分页` / `滚动`；
- 设置页：新增的「默认翻页模式」同步改为「默认翻页方式」，同样的两个选项；
- **数据层不动 schema**：`pageTurnAxis` 键仍在 JSON 里（只增不删），读回时归一为 `horizontal`；UI 写入恒为 `horizontal`；
- **txt 渲染器**分页视图轴向按视口宽度自动选（窄 → 横轴，宽 → 纵轴）；
- **阅读页首次提示**不再写方向（`滑动翻页`）——txt 与 epub 的手势本就不同，统一措辞不误导；
- Aa 面板说明文字**如实标注各格式现状**：「滚动 = 上下滑动连续阅读；分页 = 一页一页翻（epub 按屏吸附；md 暂按滚动；pdf 按文件自带页）」。

### 9.15 实施记录（v1.3.7 分页模式滚轮乱翻，2026-11-17）

用户实测反馈：「分页模式下用滚轮会出现乱翻的情况，特别是从滑动模式切回来的时候」。

#### 9.15.1 根因（实测定位）

两条叠加（widget 探针逐格记录滚轮后的落点）：

1. **落点被静默 clamp 到非页起点**。惰性列表的 `maxScrollExtent` 只是「**已构建内容**」的高度（未测到的区域没算进去；块被回收后还会回落——与 v1.3.5 滚动条跳变同一根源）。翻页目标是**页起点**，超出末尾时 `jumpTo` 会被 clamp 到末尾——一个**非页起点**的位置 → 页界失效 → 后续翻页越翻越乱。
   实测（富夹具 epub，手机视口）：第 7 格滚轮目标 3162 > 当时末尾 3056 → 落点被 clamp 到 3056；页起点链同时被写进**够不到的** 3162 → 之后每格都瞄着不可达目标 → **卡在原地不动**。
2. **弹道把页面拽回上一页**。`jumpTo` 末尾必触发一次 `goBallistic(0)`，弹道按「**就近页起点**」吸附；页起点链里若**没有刚落点这一页**，弹道就把页面拽回上一页。
   实测：落点 807.6 → 弹道把它拽回 29.84（**倒退一整页**，翻页在两页间来回跳 = 用户说的「乱翻」）。

#### 9.15.2 修法

- **落点先登记进页起点链，再跳**（`_pages.registerPageStart(clamped)` 前置到 `jumpTo` 之前）→ 弹道吸附到刚落点这一页 → 不再倒退。
- **翻页目标改用只读探测**（`peekNextPageStart` / `peekPrevPageStart`，不再用会写链的 `nextPageStart`）→ 够不到的页起点不再污染链。
- **目标必须可达**：超出末尾时先滚到末尾**逼出更多内容**（惰性构建 → 末尾变长），**下一帧**再翻（最多 4 次）；仍不可达就不翻（宁可这一格不动，也不落到页中间把页界搞坏）。
  刻意**不 await 帧**：翻页是同步手势（滚轮/按键），等一帧会把调用方卡住（widget 测试会挂住——实测 `epub_page_break_test` 直接挂死）。

#### 9.15.3 新增测试与「改坏 → 变红」

新增 `apps/sync_reader/test/reader/epub/epub_wheel_turn_test.dart`（2 例）：

1. 滚轮连翻 12 格：**每次只前进一页**（位移 ≤ 1.2 屏）、**不倒退**、落点恒为**页起点**（或已到内容末尾）；
2. 从**滚动模式切回分页**后再滚轮 5 格：同样只前进一页、不倒退。

「改坏 → 变红」实测：把「落点登记」放回 `jumpTo` **之后**（即 §9.15.1 的第 2 条）→ 用例 1 报 `Expected: >= 250.0 / Actual: 29.84`（位置倒退一整页）→ 还原后全绿。

#### 9.15.4 遗留风险

- **页起点链的「可达性」检查目前只在极端情形被触发**（末尾被低估时）：夹具 epub 的末尾估计随块回收波动 ±600px，平时翻页目标都在可达范围内；该检查是防御性的（避免链被写进不可达落点）。
- **epub 分页模式滚轮到底仍是纵向的**（连续排版 + 按屏吸附，见 07-R2）；若要让 epub 也横向翻书式翻页，是页结构层面的重构，不在本轮范围。
- 从滚动模式切回分页时，视口可能停在**页中间**（切模式不改位置）→ 该页的第一格滚轮会按页中间的偏移算，可能比一页略多（但落点仍是页起点，页界不失效）。

### 9.16 实施记录（v1.3.7 分页模式移除滚轮，2026-11-17）

用户决定：「删除分页模式滚轮相关的代码，分页模式仅允许键盘控制」。

#### 9.16.1 决策与理由

§9.15 修好了「滚轮乱翻」的**机制性缺陷**（落点被 clamp、弹道拽回上一页），
但用户最终选择**更简单的方案**：分页模式**彻底不认滚轮**。

- 分页模式的翻页只由 **键盘**（↑/↓/PageUp/PageDown/空格）与**触摸滑动**控制；
- 滚轮在分页模式下**既不翻页、也不滚动正文**（否则正文会在页中间自由滚动，
  页界随之失效 —— 这正是「乱翻」的观感来源）；
- **滚动模式不受影响**（滚轮照常滚动正文 —— 滚动模式本来就是连续滚动）。

#### 9.16.2 改动

| 位置 | 改动 |
| --- | --- |
| `txt_renderer.dart` | 删掉 `_onPointerSignal`（滚轮累积 + 过阈值翻页）与 `_wheelAccum`；改为 `_swallowWheel`：只**吞掉**滚轮事件（`PointerSignalResolver` 抢先注册 + `respond`），Scrollable 不再收到滚轮 |
| `epub_renderer.dart` | 删掉 `_onWheel`（滚轮累积 + 过阈值翻页）与 `_wheelAccum`；改为 `_swallowWheel`（同上，挂在块项内部） |
| `settings_panel.dart` | 说明文字补上键盘路径（`键盘 ↑/↓/PgUp/PgDn 或滑动`） |

**为什么还要留一个「吞滚轮」的监听**：滚轮经 `PointerSignalResolver` 分发，
只有**最先注册（最深）**的回调生效。若不抢先注册，`Scrollable` 会照常响应
滚轮 —— txt 的桌面端竖轴 `PageView` 会被滚轮推动、epub 的分页正文会被滚轮
自由滚动（页界失效）。而 `ScrollPhysics.shouldAcceptUserOffset` 无法只关滚轮
（它同时管拖拽与 `setCanDrag`，会把触摸滑动一起关掉）。

#### 9.16.3 新增测试与「改坏 → 变红」

- `test/reader/epub/epub_wheel_turn_test.dart`（改写为 3 例）：分页模式滚轮
  **位置完全不动**（不翻页、不滚动、页起点链不新增）；分页模式键盘路径
  （`nextPage`）**照常翻页**；滚动模式滚轮**照常滚动**。
- `test/reader/txt/txt_renderer_widget_test.dart`（+1 例）：分页模式滚轮**不
  推动 PageView**（页偏移不变）。

「改坏 → 变红」实测：把 epub 的滚轮处理改回「累积过阈值翻页」→ 分页模式用例
报位置变化；把 txt 的吞滚轮监听去掉 → txt 用例报页偏移变化。

#### 9.16.4 遗留风险

- **热区点击翻页与鼠标拖拽仍保留**：它们与手机端触摸滑动共用代码路径（删了
  手机就没法滑动翻页）；桌面端仍可点正文左右两侧翻页、按住拖拽翻页。
- epub 的分页手势仍是纵向（连续排版 + 按屏吸附，07-R2）；横向翻书式翻页是
  页结构层面的重构，不在本轮范围。

#### 9.17.1 分页模式禁用鼠标拖动

§9.16 已把滚轮从分页模式移除；本轮把**鼠标拖动**也移除 → 分页模式的翻页
只剩 **键盘**（↑/↓/PageUp/PageDown/空格）与**触摸滑动**。

**生效方式**：分页视图包一层 `ScrollConfiguration`，`dragDevices` 换成
「仅触摸」集合（`kReaderTouchOnlyDragDevices`，见 `reader_chrome.dart`）：

```dart
ScrollConfiguration(
  behavior: ScrollConfiguration.of(context).copyWith(
    dragDevices: kReaderTouchOnlyDragDevices,   // 去掉 mouse
  ),
  child: ...,
)
```

Flutter 的 `Scrollable` 会用 `dragDevices` 作为拖拽识别器的
`supportedDevices`（见 `Scrollable.build`），去掉 mouse 即鼠标拖动失效，
**触摸滑动照常**（手机端主交互不受影响）。

| 位置 | 处理 |
| --- | --- |
| epub 分页视图 | `ScrollConfiguration.copyWith(dragDevices: 仅触摸)`（同层已有关滚动条的 `copyWith`） |
| txt 分页视图 | 同上（包住 `PageView`） |
| **滚动模式** | **不变**：桌面仍可按住鼠标拖动滚动正文（`AppScrollBehavior` 仍含 mouse） |
| 手机端 | 不变：触摸滑动翻页照常 |

> 为什么不能用 `ScrollPhysics.shouldAcceptUserOffset` 关掉：它同时管**拖拽**
> 与 `setCanDrag`，置 false 会把**触摸滑动**一起关掉（手机端就翻不了页了）。

### 9.18 实施记录（v1.3.7 移动端分页改为左右滑动，2026-11-17）

用户反馈：「移动端分页模式从上下滑动切换为左右滑动」。

#### 9.18.1 问题与取舍

txt 的分页本来就是横轴 `PageView`（左右滑动 ✓），但 **epub 的分页是纵向的**
——它沿用 07-R2 登记的「连续排版 + 按屏吸附」方案：正文是一条**纵向**连续
列表，页界靠「停在某个位置」来切（页起点 = 纵向偏移）。移动端上下滑动因此
是唯一的翻页手势，与 txt 不一致。

要让 epub 也做「左右翻书」，需要把正文**重新分页成整页内容**（每页一个独立
的纵向切片）——那是页结构层面的重构（块要能跨页切分、插图独占页、locator、
页起点链全部重做），不在本轮范围。

#### 9.18.2 本轮做法（手势层对齐）

- **翻页手势**：epub 分页模式新增**横向拖拽识别器**（仅触摸，
  `supportedDevices` = 仅触摸集合）——左滑下一页 / 右滑上一页；
- **正文不再随手指上下滑动**：`EpubPageScrollPhysics.shouldAcceptUserOffset`
  返回 false → 分页模式**不接受用户滚动**（`setCanDrag(false)` → 触摸拖动
  也不带动正文；程序化滚动 `jumpTo`/`animateTo` 不受影响 ✓）。
  于是纵向滑动在分页模式下**完全无效**（正文不会被拖到页中间 → 页界始终成立）；
- **翻页落点逻辑不变**：仍是「跳到相邻页起点」（`_turnPageInPageMode`），
  页起点链的精确往返照旧；
- **随之清理的死代码**：纵向滑动消失后，「滑动起点基准 + 落点缓存 + 弹道吸附
  分支」整套机制（约 100 行）不再有输入来源，一并删除——分页模式的弹道只剩
  程序化跳转（速度 0，平台默认物理直接返回 null ✓）。

> 视觉说明：epub 的正文仍是纵向连续排版（按页裁剪显示），所以左右滑动之后
> 是「纵向跳页」而非 txt 那种横向翻书动画。要横向翻书动画，需要把 epub 正文
> 重新分页成整页内容（页结构层面的重构）。

#### 9.18.3 新增测试与「改坏 → 变红」

`test/reader/epub/epub_swipe_test.dart`（改写为 3 例）：

1. **左滑** → 前进一页，落点是**页起点**；
2. **右滑** → 精确回到上一页（页起点链保证往返）；
3. **纵向滑动无效**（分页模式不接受用户滚动，正文不会被拖走）。

「改坏 → 变红」实测：去掉横向拖拽识别器 → 用例 1、2 报位置不变

### 9.19 实施记录（v1.4.1 删除语义回归：删除即移出书库，2026-11-18）

用户实测反馈：「从云端和本地都删除的书籍还是会在书库中出现」（截图：书库页
仍有两条「未下载」卡片，云端书库页已无对应条目）。

#### 9.19.1 根因

v1.1 的删除语义（§4.7b）是「删正文、**留元数据**」：本地删除只把
`books.local_path` 置 NULL、`books` 行保留 → 该书落进书库的「未下载」桶，
**永久显示**。而「从云端移除」（`SyncEngine.removeCloudCopy` → `deleteMeta`）
只删云端 meta 文件、**完全不动本地行**。两边都删完 → 本地那行成了永久残影。

更糟的是**同一语义两端表现不一致**：别的设备删的书在本机**消失**
（`applyRemoteMeta(tombstone)` 删 `books` 行），本机删的书在本机**留着**。
且文档里写的「90 天 tombstone GC 后消失」从未发生——GC 只清 `deleted_books`
账本，没人删那行 `books`。

#### 9.19.2 本轮做法（删除即移出书库）

- `BooksDao.softDelete()` → `BooksDao.deleteBook()`：**删 `books` 行**
  （进度 / 按天阅读时长随之级联清除）+ 删正文/封面文件 + 写墓碑账本 +
  清「仅本地」标记（书没了标记也失效，否则「未上传的书」计数虚高）。
- **schemaVersion 4 → 5（纯数据迁移，DDL 不变）**：清理**存量**残影——旧版
  「删正文、留元数据」已经在用户库里留下的「有墓碑的 `books` 行」（就是用户
  截图里那两条「未下载」卡片）。迁移删掉这些行 + 其 `progress` /
  `reading_days` / `local_only_books` 子行（迁移在事务内跑、
  `PRAGMA foreign_keys` 尚未生效 → 级联不会自动触发，显式先删）；**墓碑账本
  保留**（它才是「已删除」的留痕：驱动云端 tombstone 推送与 90 天 GC）。
- `DriftLocalLibrary.applyRemoteMeta(tombstone)`：**两种来源都删 `books` 行**
  （本端自己删的通常是幂等兜底；它真正兜住的是「墓碑还没推上去、书却被
  别的设备改活」的竞态——那次拉活会重建 `books` 行（占位书），墓碑回来时
  必须把它收走，否则书库里留下复活残影）。墓碑账本的**记账不被覆盖**
  （`pushed=false` 是「待推墓碑」的记账，覆盖成 true 会让离线删除的墓碑
  永远推不出去）。
- `DriftLocalLibrary.listBooks()`：墓碑排除保留为**兜底**（本地删除已无
  `books` 行），防「墓碑已记账但行仍在」的竞态把书推回云端。
- 文案：`kDeleteBookDialogBody` 改为「本书会从书库移除（阅读进度一并清除）」。
- 墓碑推送**不受影响**：本地行已删时，引擎从 `sync_state` 的上次同步副本
  （公共祖先）取墓碑内容照常上云（`sync_facade_test` 已有该路径用例）。

#### 9.19.3 代价（已知取舍）

- 误删没有一键恢复（云端正文文件仍在，但云端 meta 已变墓碑，本端不再展示
  该书，没有「点下载正文」的入口）；找回只能重新导入本地文件（新的 bookId）。
- 重新导入同一文件**不恢复**阅读位置（进度随书级联清除）。注：v1.1 文档里
  「同文件重新导入后可恢复位置」本就**没有实现**——导入去重命中 `contentHash`

- 云端正文仍不删（docs/04 §7.1 规则 4 不变式），删除产生的云端孤儿文件

### 9.20 实施记录（v1.4.2 UI 字体栈分平台解析，2026-11-18）

用户实测反馈：「当前项目系统用的什么字体，好奇怪，得换常见字体」（截图：书库
列表页书名渲染成一支**细体几何黑体**，与拉丁字母像两种字体，标题字重也不生效）。

#### 9.20.1 根因

`AppFonts.ui` 此前**硬写 `'Roboto'`**，而 Roboto 是 **Android 原生字体**，
Windows 上**根本没装**（`C:\Windows\Fonts` 里没有任何 `roboto*.ttf`）。于是：

1. 拉丁文字落到引擎的平台默认字体（Segoe UI）——碰巧还算体面；
2. 汉字落到 **DirectWrite 的系统回退链**——命中哪支字体由机器的字体安装情况
   决定（本机命中一支细体几何黑体），**与拉丁不同源**；
3. 该字体没有与请求字重（标题 `w600`）对应的字面 → 字重被抹平，标题不粗。

结果就是截图里的观感：中英像两种字体、整页发飘。**文档 §3.2 本来就写的是
「按平台」（Win 用 Segoe UI、And 用 Roboto）**，代码没实现——是实现漏了分平台，
不是设计如此。

#### 9.20.2 本轮做法

- `AppFonts.ui` 改为**按 `defaultTargetPlatform` 解析**：
  Win `Segoe UI` / And `Roboto` / macOS+iOS `Helvetica Neue` / 其余 `Noto Sans`。
- 新增 `AppFonts.uiFallback`（**CJK 显式回退栈**）：
  Win `Microsoft YaHei UI` → `Microsoft YaHei` → `Noto Sans SC`；
  And `Noto Sans SC` → `Noto Sans CJK SC`；macOS/iOS `PingFang SC` → `Heiti SC`；
  Linux `Noto Sans CJK SC` → `WenQuanYi Zen Hei` → `DejaVu Sans`。
  有了它，汉字不再走「各机器不同的系统回退链」，而是落到该平台**通用的中文字体**
  （Windows 微软雅黑、macOS 苹方、Linux/And 思源黑体），且这些字体都有真正的
  Bold 字面 → 标题字重终于生效。
- 字阶 `_style()` 与 `ThemeData` **都**带上 `fontFamily` + `fontFamilyFallback`：
  只给字阶加，`ThemeData` 自己拼的字（输入框、菜单、悬浮提示）仍会落回
  typography 的 'Roboto' → 回退链又乱了。
- 阅读正文的三档（宋体/黑体/楷体）与回退栈**不动**——它们本来就是显式栈，
  且用户在设置页可自选。

#### 9.20.3 验证（真机 A/B，同书库同页面）

- 改前（`'Roboto'` → 系统回退）与改后（`Segoe UI` + 微软雅黑）各截一次
  Windows release 窗口，同一页同一批书：书名「恶女不才，请多关照！～」等
  从**细体几何黑体**变为**微软雅黑**（笔画增粗、字重生效）。
- 量化：同一区块（设置页标题「赭石」）暗像素占比 **6.20% → 7.99%**（+29%）。
- 仍**不打包任何字体文件**（Q4 不变，NFR-04 体积门不受影响）。
