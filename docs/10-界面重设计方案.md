# 10 · 界面重设计方案（v1.0.0 之后）

> 状态：**设计规范（已实施）**。本文档只描述最终设计；`ui_prototype/` 原型为设计依据（阅读页原型 `reader.html`），实施过程与逐版本改动记录见 git 历史与 CHANGELOG。
> 目标：把 SyncReader 从「能用」提升到「愿意每天用」——书库要像书架，阅读器要像书，同步要像后台而不是噪音。

## 1. 现状审计（v1.0.0 真机截图 + 源码）

在 Windows 12 / 2560×1440 上跑 `build/windows/x64/runner/Release/sync_reader.exe` 抓图，对照源码逐屏走查，结论如下。

### 1.1 布局与层级

| # | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| L1 | **内容宽度割裂**：同步状态条与搜索框通栏（≈1230px），书卡网格却固定 `maxCrossAxisExtent: 150` 缩在左侧 150px | 真机截图：搜索框横贯整窗，书卡只有一小块，其余全是空白 | 大屏上像「坏掉了」，信息密度极低 |

### 1.4 细节

- 封面角标 9px、`SyncBadge` 用 `Colors.orange.shade700` 等 Material 散色，与主题脱节。
- 错误/警告文字统一 11~12px，信息层级靠字号硬压。
- 危险操作（清除凭据、删除）与常规项混在同一列表，无视觉分区。

## 2. 设计目标

1. **书库像书架**：一眼看完「有多少本、读到哪、哪些没同步」，而不是「一堆文件」。
2. **阅读器像书**：正文是主角，控件是配角，随时可隐去。
3. **同步是后台**：状态常驻可见但不喧哗；异常才升级为提示。
4. **一套令牌，全局一致**：色彩/字阶/间距/圆角全部集中定义，Flutter 侧落地为 `ThemeExtension`。
5. **跨端自适应**：桌面宽屏用左栏 + 多列；窄窗收成图标栏；移动端改底部标签栏。

## 3. 设计系统

完整可视化见原型「设计规范」页（`ui_prototype/index.html` → 顶部「设计规范」）。

### 3.1 色彩

中性色**带暖调**（纸感）；品牌色为低饱和暖调（默认赭石），不直接使用 `colorSchemeSeed: Colors.teal` 的高饱和塑料感。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--bg` | `#F6F5F1` | `#121317` | 应用底色 |
| `--surface` | `#FFFFFF` | `#1A1C21` | 卡片 |
| `--surface-2` | `#FAF9F6` | `#212429` | 次级填充 |
| `--border` | `#E4E2DB` | `#2C3038` | 1px 描边 |
| `--text` | `#1D1C1A` | `#E9E7E2` | 主文字 |
| `--text-2` | `#6A6862` | `#9EA2AB` | 次要文字 |
| `--success/--warn/--danger` | `#1F7A4D` / `#A95B06` / `#B42318` | 对应提亮版 | 状态语义 |

**品牌风格（accent）可切换**，默认**赭石**（纸墨暖调），用户可在「设置 → 外观」中改。

| 风格 | 浅色主色 | 深色主色 | 气质 |
| --- | --- | --- | --- |
| **赭石（默认）** | `#B25430` | `#E08A62` | 纸墨暖调，贴「读书」这件事 |
| 青瓷 | `#0E7A6E` | `#35B8A3` | 清冷沉静（原 teal 基因，去饱和） |
| 墨绿 | `#2F5D4F` | `#6FBB9F` | 线装书气质 |

每套 accent 含 5 个变量：`--brand` / `--brand-hover` / `--brand-soft`（选中底色）/ `--brand-soft-2` / `--brand-text`（软底上的可读文字色）。
Flutter 侧落为一个 `AppAccent` 枚举 + `ThemeExtension`，持久化到 `app_settings` 表（只增不删迁移）。

**阅读主题独立于应用主题**（可在阅读器内单独切换）：

| 主题 | 背景 | 正文 | 说明 |
| --- | --- | --- | --- |
| 纸白 | `#FFFFFF` | `#26251F` | 默认 |
| 米黄 | `#F6EFE0` | `#40382B` | 暖米色纸张 |
| 护眼 | `#E5EEE2` | `#2B3529` | 淡绿护眼 |
| 夜间 | `#14151A` | `#C8CACD` | 低对比暖黑 |

### 3.2 字体

**不打包中文字体**（体积代价 17–25MB，与 NFR-04 体积门冲突），全部走系统字体栈：

- **UI**：**按平台解析**（`AppFonts.ui` + `AppFonts.uiFallback`）——
  Win `Segoe UI` + CJK `Microsoft YaHei UI`/`Microsoft YaHei`；Android `Roboto` +
  CJK `Noto Sans SC`/`Noto Sans CJK SC`；macOS/iOS `Helvetica Neue` + CJK
  `PingFang SC`；Linux `Noto Sans` + CJK `Noto Sans CJK SC`/`WenQuanYi Zen Hei`。
  CJK **必须显式列回退族**——不列就交给引擎的系统回退链，落到哪支字体各机器
  不同（Windows 上曾落到一支细体几何黑体，中英像两种字体）。
- **阅读正文**：`Noto Serif SC` / `Source Han Serif SC` / `Songti SC` / `SimSun` → 宋体阅读感。
- **可选第三档**：`KaiTi` / `STKaiti` 楷体。

字阶（UI 基准 14px）：

| 名称 | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| display | 30/38 | 680 | 书名、页面主标题 |
| h1 | 22/30 | 620 | 章节标题 |
| h2 | 18/26 | 650 | 页面标题、卡片标题 |
| h3 | 15/22 | 620 | 分组标题 |
| body | 14/22 | 400 | 正文、列表主行 |
| sm | 13/20 | 400 | 次级正文 |
| caption | 12/18 | 400 | 辅助说明 |
| micro | 11/16 | 600 | 标签、角标 |

**所有角标 / 徽标字号不小于 11px。**

### 3.3 间距与圆角

- 间距 4px 基准：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。
- 圆角：`6`（chip）/ `10`（按钮、封面）/ `14`（卡片）/ `20`（大面板）。
- 阴影：三级极浅投影（`0 1px 2px` → `0 14px 36px`），层级主要靠表面色差 + 1px 描边。

## 4. 页面方案

### 4.1 应用外壳

- **桌面 ≥1180px**：左侧导航栏 232px（品牌区 / **书库 · 同步 · 设置** / 底部同步状态胶囊）。
- **窄窗 1180px 以下**：导航栏收成 68px 图标栏。
- **移动 ≤860px**：隐藏侧栏，改底部标签栏（书库 / 同步 / 设置）。
- 顶栏统一：页面标题 + 副标题 + 右侧动作区，1px 底边线。
- **导航只保留三项**：「工具」分组与工具索引页取消（见 §4.8），其功能按下述方式安置：
  - 导入 → 回到书库顶栏（分裂按钮）；
  - 未上传的书 → 同步页的「未上传的书」卡片；
  - 云端书库管理 → 同步页的「云端书库」入口 → 独立页。

### 4.2 书库

#### 两层筛选（取交集）

筛选拆成**两层**，两层**同时生效、取交集**（不是互斥四选一）：

| 层 | 控件 | 取值 |
| --- | --- | --- |
| 第一层 · 状态 | 常驻 chip 行（互斥单选） | `全部` / `已同步` / `仅本地` / `仅云端` |
| 第二层 · 分组 | 下拉菜单（互斥单选） | `全部分组` / `未分组` / 各分组 / `管理分组…` |

**第一层是四个互斥桶**（云端轴「云端有无」× 本地轴「本地正文有无」组合）：

| 桶 | 定义 | 封面角标 |
| --- | --- | --- |
| `已同步` | 云端有 + 本地有正文 | 阅读百分比 / `待上传` / `同步失败` |
| `仅本地` | 云端没有 + 本地有正文 | `仅本地` |
| `仅云端` | 云端有 + 本地没有正文 | `未下载` |

四态互斥、计数不重叠。**「已删除」的书不在书库里**（删除即移出书库，§4.7b）——`仅云端` 桶只剩真正的云端占位书（其它设备上传、本端还没有正文）。

- **分组不平铺**：分组数量不可控（用户可自建），平铺成 chip 行会挤爆版面，故用一个下拉。按钮上显示当前选中的分组名（`📂 小说 ▾`）。
- **计数是分面计数（faceted count）**：第一层 chip 上的数字 = 在当前分组筛选下该状态有多少本；第二层下拉里的数字 = 在当前状态筛选下该分组有多少本。两个数字互相联动，用户能提前看到「换一层会剩多少」。
- 右侧灰字给出结果概要：`共 42 本` 或 `匹配 3 / 42 本`。
- 两层交集为空时给出空态（图标 + 说明 + 「清除筛选」按钮），而不是一片空白。
- **不设「在读 / 未读」维度**：在读与否是「进度」而不是「状态」，交给右上角「最近阅读」排序表达；混进筛选会让维度语义不清。

#### 书卡交互

- **点封面直接打开书**：书卡上没有任何常驻按钮，也不做 hover 浮层。点击封面 = 打开该书（未下载的先触发下载）。
- **信息入口用手势**：
  - 桌面端 **右键** 书卡 → 弹出上下文菜单；
  - 移动端 / Pad **长按** 书卡 → 弹出同一个上下文菜单。
  - 菜单项：`继续阅读（xx%）` / `下载正文`（未下载时）/ `书籍信息` / `移动到分组…` / —— / `删除本书`（危险色）。
- **封面右上角状态胶囊**（不使用封面底部的黑色 `98%` 遮条）：
  - 已下载且在读 → **阅读百分比**（品牌色胶囊，如 `62%`）；
  - 未下载 → `未下载`（墨色胶囊）；
  - 同步异常 → `待上传`（琥珀）/ `同步失败`（红）。
  - 卡片下方的文字行只留「⏱ 阅读时长」，百分比不再重复。
- **手势冲突**：FR-107 的「长按拖拽归组」与「长按出菜单」在触屏上冲突。
  **方案**：桌面端保留拖拽归组 + 右键菜单；触屏端不使用拖拽归组，统一走菜单里的「移动到分组…」。

#### 其它

- 筛选常驻可见（不藏在弹层里），解决 I2。
- **生成封面用「纸底墨字」**：无真封面（txt / 部分 epub）时用**极低饱和的纸底 + 同色系深墨首字 + 内框线 + 标题/作者排版 + 品牌色小横线**。底色/墨色/框线由内容哈希取同一色相（饱和度 12%、亮度 90%），既保留每本书的辨识度，又不与赭石品牌打架。
- **网格**：卡宽 154px 起（`auto-fill minmax(154px,1fr)`），封面圆角 10px + 轻投影；hover 上浮 3px 并浮出「继续 / ⋯」操作条。
- **进度**：**封面下沿 3px 品牌色进度条**。
- **列表模式**：行高 78px，右侧 120px 线性进度 + 百分比；移动端隐藏进度条只留百分比。
- **状态角标**：`仅云端` / `待上传` / `同步失败` 统一为封面左上角胶囊（11px）。
- **同步状态条置于内容区之外**，收进左下角胶囊；仅在配额超限/同步失败时，内容区顶部才插入提示条。解决 I1。
- **搜索框**在桌面进顶栏、在移动端落进内容区。

#### 导入（兼容单文件与批量）

- 顶栏导入用**分裂按钮**：主区「＋ 导入」= 导入文件；箭头展开「导入文件… / 批量导入（文件夹）」。单文件与批量两条路径在同一个入口下。
  按钮**高度贴着内容**（32px，箭头那半边的点击区同步收紧）——背景色块不得高过内容。
- **导入确认弹窗**（两条路径共用）：文件清单 + 「**同时上传到云端**」勾选（**默认勾选**）+ 上行流量预估（`预计上行 42.6 MB · 坚果云免费额度 1 GB / 月`）。取消勾选时提示切换为「不上传：不消耗上行流量，其它设备看不到这几本书」。
- 取消勾选导入的书标记为「仅本地」，封面右上角显示「仅本地」角标。

### 4.3 书籍详情

- Hero：大封面 168px + 阴影，右侧标题（display 30px）/ 作者 / 标签 / **进度条 + 「62% · 第 128 章」** / 主操作按钮组。
- 「阅读数据」卡片：4 个统计块 + 近 7 天阅读量柱状图。
- 「文件信息」卡片：定义列表（文件名/大小/哈希/添加时间/同步根）。
- 「目录」卡片：**目录预览**（章节目录列表）。

### 4.4 阅读器

> 依据原型 `ui_prototype/reader.html`（交互逻辑与功能说明稿）与决策 Q22–Q25；
> 沉浸态、点击热区、默认分页等规格见本节各条。

- **整行分页（A23，本代阅读器的地基）**：txt 分页按**整行切页**——先用
  `TextPainter.computeLineMetrics()` 量出每行的行盒边界与行首字符偏移，
  再**在行与行之间下刀**：任何一页的行要么整行可见、要么完全不可见，
  页尾不足一行时留白、绝不切字。
  每页行数恒定 → 页底留白恒定，上下留白不随内容长短跳动。
- **阅读背景 7 套（A24）**：白色 / 米黄 / 浅绿 / 浅灰蓝 / 深灰 / 深棕 / 纯黑。
  枚举名保持稳定（持久化兼容），展示名用朴素颜色描述；色值权威源
  为 `design_tokens.dart` 的 `ReaderPalette`。对比度按 WCAG 2.1 实算
  锁门：正文 ≥7:1（AAA）、次级 ≥4.5:1（AA）。
- **夜间亮度（A25）**：80%–130% 的整屏亮度系数（背景与正文一起变暗/变亮），
  只在夜间系背景（深灰/深棕/纯黑）出现；80% 下限保证正文对比度仍达 AAA。
- **排版面板（A26）**：入口图标用**齿轮**；面板提供段距（紧/空一行/
  空两行，以整行为单位）、首行缩进开关（2em ↔ 不缩进）、夜间亮度（A25）、
  翻页动画（A27）四项；面板顶部实时预览跟随全部设置项，预览下方是
  **实时对比度读数**（WCAG 2.1 相对亮度实算，非写死数字）。
- **翻页动画（A27）**：分页模式的翻页**全平台统一为左右推移**
  （当前页向左推出、下一页自右推入，位移 1:1 跟手），
  四种格式（txt / epub / md / pdf）共用**同一套时长与缓动**
  （`reader_page_turn.dart` 的 `ReaderPageTurnSpec`：280ms / easeOutCubic）；
  滚动模式仍是上下滑动连续阅读。翻页路径（键盘 / 左右热区 / 音量键 / 触摸
  滑动）共用同一 `ReaderController.nextPage()/previousPage()`；翻页被
  首/末页挡住时统一**原地轻微回弹**（24px）。
  **已知差异（如实标注，不伪装成一致）**：pdf 仍是**纵向平移**（pdfrx 连续画布，
  动画由库提供，只统一了时长与边界回弹）；md 暂不支持分页，按滚动阅读。
- **页界只落在行边界**：分页视图按「页终点」裁剪，页终点 = 下一个页起点
  （行盒边界 / 插图块顶底）。**推入页（下一页的复制渲染）与当前页用同一套
  页界口径、同一套保守兜底**（页终点 → 安全边界 → 内容末尾 → **留白**）：
  候选未知时宁可页尾多留白，**绝不按整屏裁剪**——整屏的切线落在任意 y 上，
  会把一行字拦腰切断（用户实测「翻页时一闪一截断的行」）。裁剪高度
  **每帧在绘制阶段现算**，不把起翻瞬间的值冻住。
- **沉浸态与文字优先（A28）**：进场全隐（Q10）、点空白唤出/收起；
  中区热区点击前先问渲染器「该点是否落在正文文字上」（txt 为字形盒粒度、
  epub/md 为块盒粒度）——点在文字上不切换控件，只有空白处响应。
  **移动端例外**：窄视口（≤460）用「**点屏幕任意处唤出/收起
  控制条，翻页交给滑动**」——手机屏几乎被正文铺满（正文列 363 逻辑 px ≈
  屏宽 88%），没有可点的空白，「点空白才出菜单」在手机上几乎唤不出来；
  且正文可选中尚未实现，文字优先已无对象可保护。
  滑动翻页沿用 `PageView` 原生手势，**滑动过程中不会弹出控制条**
  （点击识别器在指针越过 slop 后即被否决）。桌面端保留原模型。
- **目录抽屉**：按 `TocEntry.level` 缩进渲染、当前项高亮带「当前」徽标、
  点击**立即关闭**并跳转；txt 只有章、保持扁平（层级仅 epub / md 有意义）。
- **正文标题与四周留白**：标题不画分隔线，用字号/字重/颜色分级；
  正文列宽 720 上限、四边留白稳定（A23 的行网格保证）；窄屏收敛页边距
  （`pageMargin` 四边对称，默认 24）。
- **正文字号**：默认 16。

### 4.7b 删除语义（本地删除即移出书库）

本节覆盖 FR-408 / docs/04 §7.1 的删除语义，实施时须同步更新基线文档。

> **本地删除 = 移出书库**。本地删掉的书**不再以「未下载」残影留在书库里**
> ——云端和本地都删掉的书也一样（用户实测：「从云端和本地都删除的书籍
> 还是会在书库中出现」）。同一语义在两端表现必须一致：别的设备删的书
> 在本机**消失**，本机删的书在本机也**消失**。「已删除 = 未下载」的约定
> 不成立（见 Q21）。

| | docs/04 §7.1 约定 | **现行** |
| --- | --- | --- |
| 本地 `books` 行 | 删除（移出书库视图） | **删除（移出书库）** |
| 本地正文文件 | 移入应用内「游离文件」区（不删盘） | **直接删除**（真正删盘，释放磁盘） |
| 封面文件 | 保留在游离区 | **随正文一并删除** |
| 进度行 | 随 `books` 行级联清除 | **随 `books` 行级联清除** |
| tombstone | 写 `deleted_books` + 推云端 | 不变 |
| 云端正文 | 永不删除 | 不变 |
| 其它设备收到 tombstone | 正文保留为游离文件 | 不变 |
| 该书在书库中的呈现 | 从书库消失 | **从书库消失**（书库里没有已删除的书） |

**为什么这样定**：

① 用户实测——云端 + 本地都删掉的书仍留在书库里（残影永久显示，且文档里说的
  「90 天 GC 后消失」从未发生——GC 只清账本，没人删那行）；
② 语义不一致比「占位书 vs 已删除书难以区分」更伤——同一个删除动作，
  在别的设备上消失、在本机留着，用户无法建立稳定心智模型；
③ 墓碑账本（`deleted_books`）已经把「已删除」这个状态**记在数据层**，
  书库视图不需要（也不应该）再靠一条残行去表达它。

**配套实现要点（三个必须落的地方，缺一个就会出问题）**：

1. `BooksDao.deleteBook()`：**删 `books` 行**（进度 / 按天阅读时长随之级联清除）
   + 删除正文/封面文件 + 写 `deleted_books` 墓碑 + 清「仅本地」标记（书没了
   标记也失效，否则「未上传的书」计数虚高）。
2. `DriftLocalibrary.listBooks()`：**排除**在 `deleted_books` 里有墓碑的书。
   本地删除已移出书库（无 `books` 行），这里再排除一次是**兜底**：防止
   「墓碑已记账但行仍在」的竞态下被引擎当正常书推回云端，与墓碑打架。
3. `DriftLocalLibrary.applyRemoteMeta(tombstone)`：**本端已发起的墓碑要幂等**——
   若 `deleted_books` 已有该 bookId 的记录（= 本端自己删的），再次收到该
   tombstone 时**不要覆盖**已有的 `deletedAt` / `pushed` / `contentHash`
   （`pushed=false` 是「待推墓碑」的记账，覆盖成 true 会让离线删除的墓碑
   永远推不出去）。本端未发起的（其它设备删的）删行 + 正文转游离区。

**墓碑推送不受影响**：本地行已删时，引擎从 `sync_state` 的上次同步副本
（公共祖先）取墓碑内容照常推送（docs/04 §7.1 规则 1）。

**UI 上不区分「已删除」与「未下载」**：书库里**没有**已删除的书，
「未下载」区只剩真正的云端占位书（其它设备上传、本端还没有正文）。

**重新下载一本已删除的书**：删除即移出书库，书库里没有「点下载正文」的
入口。云端正文仍在（永不删除），但云端 meta 已变墓碑，本端不再展示它；
需要找回只能重新导入本地文件（会得到一个新的 bookId）。

**删除确认弹窗文案**：

> 删除后的行为：
> · 本书会从书库移除（阅读进度一并清除）；
> · 本地正文文件立即删除（释放磁盘空间，不可恢复）；
> · 删除标记会同步到云端，其他设备的此书也会从书库移除（它们的正文文件仍保留）。
>
> 不会删除你磁盘上的原始书籍文件。

### 4.7c 「仅本地 / 未上传」状态

**定义**：一本书**本地有正文、云端没有**，且本端**不会自动把它传上去**。
统一的心智模型：**「这台设备自己导入过一次，但没有上传」**。

**两种来源，用户看到的是同一个状态**：

| 来源 | 产生方式 | 内部状态 |
| --- | --- | --- |
| 导入时选「不上传」 | 导入弹窗取消勾选「同时上传到云端」 | 本地标记为仅本地（`local_only_books`），同步引擎完全看不见它 |
| 「从云端移除」后 | 云端管理里把书从云端删掉 | 云端 meta 已删且**不写 tombstone**；本端因仍有 `baseRev`，diff 落到**第 7b 行「云端缺失」→ 保留本地、不删不推** |

两种来源的反向操作都是「**上传到云端**」，恢复成正常同步的书。

**书库里的表现**：封面右上角「仅本地」角标；右键菜单有「上传到云端」/「设为仅本地」。

**同步页的「未上传的书」卡片**列出两类：
1. **仅本地的书**（有书目行）→ 上传 = 解除仅本地标记 → 下次同步走 diff 第 7a 行「本端新书上架」→ 推 meta + 传正文；
2. **游离文件**（只有正文文件、书目行已随删除消失）→ 上传 = 按 `contentHash` 重新关联回书库（FR-408 既有挂回逻辑）+ 上架。

**配套实现要点**：

1. **本地表 `local_only_books(bookId)`**。`books` 表不允许加列（docs/05 §5 DDL 是同步语义的一部分），但有 `book_groups` 这个「纯本地、不同步」的先例，同样处理。需同步更新 docs/05 §5 与 `schemaVersion` 迁移。
2. `DriftLocalLibrary.listBooks()`：**必须排除**仅本地的书 → 它们永不进 diff → 既不推 meta 也不传正文。
3. `pushBookMeta()`：**必须跳过**仅本地的书 → 读进度时也不能把它顺手推上云（进度防抖路径 docs/04 §3 触发时机 3）。
4. 「上传到云端」= 删掉 `local_only_books` 行 + 触发一次全量同步 → diff 第 7a 行 → 上架 meta + 正文。
5. 「从云端移除」= 调 `BackendAdapter.deleteMeta(bookId)`（**不是** `deleteBook()`——后者是推 tombstone 的全局删除）。后端已有 `listMetas()` 与 `deleteMeta()` 两个能力（`backend_adapter.dart`），正好够用，无需新增适配器接口。
6. **副作用**：从云端移除后，本端这本书落到 diff 第 7b 行，不会自动再上传；要恢复需「重新上架」（清掉 `sync_state` 的 `baseRev`）。

### 4.8 云端书库管理

「工具」分组（批量导入 / 游离文件管理 / 云端孤儿清理）与工具索引页**整体取消**，功能按下述方式安置：导入回书库、游离文件并入同步页的「未上传的书」、云端孤儿清理不设独立页。

**为什么要有这个页**：书库里只有**本地有**的书；云端还有**别的设备上传的、你本地没有**的书。从云端视角清理书库是书库页做不到的。

- 顶部说明条（蓝）：「『从云端移除』只删掉云端副本：**各端本地文件保留、照常可读**，但也不会自动再传回云端；任一端都可以随时重新上传。」
- 列表每行：勾选框 + 书名 + 格式·大小 + 本地状态胶囊（`本地已下载` / `仅云端`）+ 「从云端移除」按钮。
- 底部操作条：已选数量 + 「全选」+ 危险色「从云端移除」。
- **删除语义**：只移除云端副本（`deleteMeta`），**不写 tombstone**；各端本地副本保留（见 §4.7c）。

**入口调整**：
- 工具索引页不设（导航只留三项）。
- 游离文件管理并入同步页「未上传的书」卡片（含「上传到云端」动作）。
- 云端孤儿清理不设独立页（语义不清；云端无书目的正文直接清掉即可）。

**批量导入页保留**，入口在书库顶栏分裂按钮（§4.2）。

### 4.9 首启引导页

首次启动时给新用户一次「坚果云同步」的初始化机会，**可跳过**；跳过后不再打扰。
实现见 `lib/features/onboarding/onboarding_page.dart` 与 `lib/app/onboarding.dart`。

**版式**：

```
品牌标（蜂蜜黄应用图标 + SyncReader + 阅读进度同步）
→ 坚果云卡：图标块「坚」+ 坚果云同步 / 免费 + 分隔线 + 三条好处（图标 + 短词 + 一句说明）
→ 主按钮「配置坚果云同步 →」
→ 次按钮「暂不配置，先用本地」
```

- **没有大标题、没有副标题、没有免责说明框**：文案只留卡片与两条按钮（与全站「文案精简」口径一致）。
- 卡片头复用同步设置页的「坚」图标块；三条好处用软底图标 + 短词 + 一句说明。
- 页面在**应用外壳之外**（无侧栏/底栏）：首屏还没有导航可言。
- 内容**垂直居中**（比视口矮时居中；比视口高时可滚动，不截断按钮）。

**行为**：

| 动作 | 结果 |
| --- | --- |
| 「配置坚果云同步」 | 进入四步向导（首启专用路由 `/onboarding/guide`，同样不套外壳）；向导保存成功后回首启页并完成首启 |
| 向导中途返回 | 留在首启页，可重试或跳过 |
| 「暂不配置，先用本地」 | 落首启标志后直接进书库（同步保持未配置，沿用外壳角标 / 同步页 / 书库横幅三处既有提示，不做二次打扰） |

**首启判定**：

- 标志键 `app.onboarding.done`（`app_settings` 表，值 `'1'`）；不存在 → 未完成首启。
- 标志在**首帧之前**读回（`main.dart`）：路由 redirect 第一次求值时状态已是终态，首启页与书库之间**不闪一帧**。
- 读表失败按「已完成」处理——首启页绝不阻断启动；落库失败则内存态照常切到「已完成」（下次启动再问一次）。
- 判定未出结果时（测试环境）一律不拦路。

| Q21 | 「已删除」是否单列状态 | **不单列**：**删除即移出书库**，书库里没有已删除的书；「已删除」只留在数据层（墓碑账本 `deleted_books`） |
| Q20 | 第一层筛选的维度 | **四态互斥分区**：`全部` / `已同步`（云端有+本地有正文）/ `仅本地`（云端没有）/ `仅云端`（云端有+本地没正文）。「已下载/未下载」拆成「已同步+仅本地」与「仅云端」 |

| Q17 | 游离文件管理的形态 | **并入同步页「未上传的书」卡片**，动作为「**上传到云端**」（本地有云端没有 → 可上传） |
| Q18 | 导入时是否上传 | 导入弹窗加「同时上传到云端」勾选，**默认勾选** |
| Q19 | 云端管理的删除语义 | **只移除云端**，各端本地副本保留且照常可读，也不会自动再上传；任一端可随时重新上传（等价于「各设备各自导入过一次但没上传」） |
| Q15 | 书卡交互 | **点封面直接打开书**（无 hover 浮层）；信息入口 = 桌面右键 / 触屏长按的上下文菜单；未下载与阅读百分比进度显示在**封面右上角** |
| Q14 | 本地删除后正文文件的去留 | **直接删除**（正文文件真正删盘，释放磁盘）；其它设备删的书仍保留为游离文件（docs/04 既有语义不变） |
| Q22 | 阅读主题套数与命名（调整 Q5） | **7 套**：白色/米黄/浅绿/浅灰蓝/深灰/深棕/纯黑；**枚举名保持不变**（paper/beige/green/dark + slate/dusk/ink），中文 label 用朴素颜色描述——持久化兼容优先 |
| Q23 | 夜间亮度范围 | **80%–130%**：70% 时正文对比度跌破 AAA，下限取 80% 并由对比度门测试锁定；亮度作用于**整屏**（背景与正文一起变） |

| Q25 | 段距的计量单位 | **整行**（空一行/空两行 = 插入整行空行），不用 CSS margin——保证行网格不被破坏、每页行数恒定、页底留白不跳动 |
