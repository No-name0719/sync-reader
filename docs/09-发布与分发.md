# 09 - 发布与分发

> **TL;DR**：本文是 M4 首发分发（2026-10-28 拍板）的操作基线：版本号策略、Android 正式签名、构建打包、Inno Setup、GitHub Releases 发布流程与第三方声明。发布契约（版本号单点、产物命名、体积门）与打包脚本 `scripts/package_release.ps1` 严格一致，改动任一侧必须同步另一侧，不得漂移。

---

## 1. 版本号策略

### 1.1 单点维护

版本号唯一来源：[`apps/sync_reader/pubspec.yaml`](../apps/sync_reader/pubspec.yaml) 的 `version` 字段，格式 `major.minor.patch+build`（semver + build 号），首发为 `1.0.0+1`。任何端、任何脚本不得另行硬编码版本；需要版本号时一律从 pubspec 读取。

### 1.2 三端取版本方式

| 端 | 版本来源 | 说明 |
| --- | --- | --- |
| Android | Flutter 构建自动注入 | `versionName` = semver（如 `1.0.0`）；`versionCode` = build 号 + 1000×ABI 序号（`--split-per-abi` 时 Flutter 自动累加，保证各 ABI 的 versionCode 互斥且随 build 递增，见 `android/app/build.gradle.kts` 注释） |
| Windows | `FLUTTER_VERSION` 宏 | `windows/runner/Runner.rc` 通过 `FLUTTER_VERSION_MAJOR/MINOR/PATCH/BUILD` 宏取版本，构建时由 flutter 工具从 pubspec 生成，**无需手工同步** |
| 安装器 | 打包脚本传入 | Inno Setup 脚本的版本由 `scripts/package_release.ps1` 传入（默认从 pubspec 读取，或用 `-Version` 显式指定），与 semver 保持一致 |

### 1.3 tag 与产物命名

- tag 规则：`v{semver}`（如 `v1.0.0`），**不含 build 号**；
- 产物命名同样用不含 build 号的 semver：

| 产物 | 说明 |
| --- | --- |
| `SyncReader-v1.0.0-android-arm64-v8a.apk` | Android arm64（主流机型，首选） |
| `SyncReader-v1.0.0-android-armeabi-v7a.apk` | Android 32 位 ARM（老设备） |
| `SyncReader-v1.0.0-android-x86_64.apk` | Android x86_64（模拟器） |
| `SyncReader-v1.0.0-windows-x64-setup.exe` | Windows Inno Setup 安装器 |
| `SyncReader-v1.0.0-windows-x64-portable.zip` | Windows 便携包（解压即用） |

- 产物统一输出到仓库根 `dist/`；
- build 号（`+1`）仅体现在 Android `versionCode`，用于系统识别升级序号，不出现在 tag 与产物名中。

## 2. Android 签名

### 2.1 签名材料与保管状况

| 材料 | 位置 | 状况 |
| --- | --- | --- |
| keystore | `apps/sync_reader/android/key/syncreader-release.jks` | PKCS12 格式，alias `syncreader`，有效期 100 年（36500 天） |
| 密码配置 | `apps/sync_reader/android/key.properties` | 含 `storeFile` / `storePassword` / `keyAlias` / `keyPassword` 四键；`storeFile` 路径**以 `android/`（gradle rootProject）为基准**（如 `key/syncreader-release.jks`），构建脚本用 `rootProject.file()` 解析 |

两者均已在仓库根 [.gitignore](../.gitignore) 排除（`apps/sync_reader/android/key.properties` 与 `apps/sync_reader/android/key/` 两条），**绝不入库**，也不会出现在任何提交历史中。

### 2.2 凭据优先级（build.gradle.kts）

`android/app/build.gradle.kts` 逐键取值：`System.getenv(ENV) ?: key.properties[key]`，即**环境变量优先于 key.properties**：

| 环境变量 | 对应 key.properties 键 |
| --- | --- |
| `SYNCREADER_KEYSTORE_FILE` | `storeFile` |
| `SYNCREADER_KEYSTORE_PASSWORD` | `storePassword` |
| `SYNCREADER_KEY_ALIAS` | `keyAlias` |
| `SYNCREADER_KEY_PASSWORD` | `keyPassword` |

材料齐备（keystore 文件存在 + 四个值齐）时 release 构建用正式签名；**两组材料都缺失时 release 回退 debug 签名**，仅供本机冒烟（见 §2.6）。

### 2.3 首次生成 keystore（keytool 命令示例）

```bash
keytool -genkeypair -v \
  -keystore apps/sync_reader/android/key/syncreader-release.jks \
  -storetype PKCS12 \
  -alias syncreader \
  -keyalg RSA -keysize 2048 -validity 36500 \
  -storepass '<storePassword 占位，自行替换>' \
  -keypass '<keyPassword 占位，自行替换>' \
  -dname "CN=SyncReader, OU=SyncReader, O=SyncReader, C=CN"
```

生成后把四个实际值写入 `apps/sync_reader/android/key.properties`（`keytool` 在 JDK 17 的 `bin/` 下，本机 JDK 位置见 [docs/08 §1](./08-开发环境搭建.md)）。

### 2.4 密码与 keystore 保管纪律

- **绝不入库**：除 §2.1 两条 gitignore 路径外，不把密码写进任何文档、脚本、注释或示例文件；
- **绝不进构建日志**：构建脚本中不用 `echo` / `set` 打印环境变量；§2.2 四个环境变量由本机环境或 `android/key.properties` 注入（CI 已于 2026-10-28 移除，见 [07-A19](./07-风险与待确认问题.md)）；一旦疑似泄露，先轮换 keystore 密码再评估是否换发新 keystore；
- **本机外需离线备份**：keystore 本体 + 两个密码做一份离线备份（加密压缩后存本机磁盘之外）；仅存本机一份等于磁盘损坏即永久丢失。

### 2.5 keystore 丢失的影响

- **无法同签名覆盖安装**：Android 要求同 applicationId 的升级包签名一致；换新 keystore 后用户须卸载重装（数据不丢，见下），但升级体验受损；
- **数据不丢**：书籍元数据与进度在云端（坚果云 meta），本地数据也可重新导入——卸载重装后重新配置同步凭据即可恢复书库与进度；
- 结论：丢失的代价是「老用户须卸载重装」而非数据灾难，但仍应按 §2.4 严防丢失。

### 2.6 debug 签名回退的适用范围

仅限开发者本机冒烟（如 `flutter run --release` 验证 release 模式行为）。debug 签名的产物**不得上传 Releases、不得分发**；发布前按 §5 自查清单核对正式签名。

## 3. 构建与打包

### 3.1 基础构建命令

```bash
# Android（按 ABI 拆分，产物在 build/app/outputs/flutter-apk/）
flutter build apk --release --split-per-abi

# Windows（产物在 build/windows/x64/runner/Release/）
flutter build windows --release
```

### 3.2 打包脚本 `scripts/package_release.ps1`（仓库根）

一键完成「构建 → 按命名契约改名归集 → 制作安装器 → 压缩便携包」，产物统一输出到 `dist/`：

```powershell
# 全量打包（Android + Windows + 安装器 + 便携包）
powershell scripts/package_release.ps1

# 只打 Android（跳过 Windows 侧）
powershell scripts/package_release.ps1 -SkipWindows

# 指定 ISCC 与输出目录
powershell scripts/package_release.ps1 -IsccPath "D:\softwares\node_env\innosetup\ISCC.exe" -OutDir "D:\tmp\dist"
```

参数表（与脚本实现严格一致）：

| 参数 | 作用 |
| --- | --- |
| `-SkipWindows` | 跳过 `flutter build windows` 及其后续形态 |
| `-SkipAndroid` | 跳过 `flutter build apk` 及其后续形态 |
| `-SkipInstaller` | 跳过 Inno Setup 安装器制作 |
| `-SkipPortable` | 跳过 zip 便携包制作 |
| `-IsccPath` | 显式指定 `ISCC.exe` 路径（探测优先级最高） |
| `-OutDir` | 产物输出目录（默认仓库根 `dist/`） |
| `-Version` | 显式指定版本号（默认从 pubspec `version` 取 semver 部分，规则见 §1.1） |

产物表与体积门（NFR-04）：

| 产物（`dist/` 下） | 体积门 |
| --- | --- |
| `SyncReader-v1.0.0-android-arm64-v8a.apk` | ≤ 60MB |
| `SyncReader-v1.0.0-android-armeabi-v7a.apk` | ≤ 60MB |
| `SyncReader-v1.0.0-android-x86_64.apk` | ≤ 60MB |
| `SyncReader-v1.0.0-windows-x64-setup.exe` | ≤ 120MB |
| `SyncReader-v1.0.0-windows-x64-portable.zip` | 无硬门（与安装器同口径自查即可） |

性能门 NFR-05（发布前抽查，非打包脚本职责）：Android 中端机冷启动 ≤2.5s、Windows ≤3s，标准见 [docs/01 §4](./01-需求规格说明.md)。

### 3.3 构建收口必看（引用，不赘述）

本机环境相关的三组坑，**细节与解法一律见 [docs/08](./08-开发环境搭建.md)**，构建失败时优先排查：

- pdfium 手动预置（Windows / Android 落点不同，Android 必须预置到 `.lib` 持久缓存）：[docs/08 §6.3.1](./08-开发环境搭建.md)；
- Windows 插件符号链接（junction 免管理员绕过）：[docs/08 §6.3](./08-开发环境搭建.md)；
- Android release 构建三坑（Kotlin 增量缓存 / `GRADLE_USER_HOME` 必带 / INTERNET 权限）：[docs/08 §6.3.2](./08-开发环境搭建.md)。

## 4. Inno Setup（Windows 安装器工具链）

- **官方下载渠道**：<https://jrsoftware.org/isdl.php>（Inno Setup 6 稳定版；仅打包机需要安装，普通构建者无需）。
- **两种安装方式**：
  - **管理员方式**：以管理员身份运行官方安装包，默认 per-machine 装到 `C:\Program Files (x86)\Inno Setup 6`；
  - **无管理员方式**：普通权限运行并选择仅当前用户安装，或静默安装：

    ```
    innosetup-6.x.x.exe /VERYSILENT /SUPPRESSMSGBOXES /CURRENTUSER /DIR="D:\softwares\node_env\innosetup"
    ```

- **ISCC 探测顺序**（打包脚本与本文严格一致）：`-IsccPath` 参数 → 环境变量 `INNO_SETUP_HOME`（取其下 `ISCC.exe`）→ 三个常见安装路径 → 均未命中则**警告并跳过安装器形态**（APK 与便携包不受影响）。装在非默认目录时，设好 `INNO_SETUP_HOME` 环境变量或用 `-IsccPath` 指定即可。

## 5. GitHub Releases 发布流程（A15）

首发与后续版本统一走 GitHub Releases 直发（应用商店上架为 P2，见 [docs/07 A15](./07-风险与待确认问题.md)）。流程：

1. **收口检查**：CHANGELOG 已写本版本条目；`flutter analyze` 与测试全绿；性能门抽查通过（NFR-05）。
2. **打 tag**：`git tag v1.0.0 && git push origin v1.0.0`（tag 与 pubspec 的 semver 一致，见 §1.3）。
3. **构建产物**：在打包机全量运行 `scripts/package_release.ps1`，核对 `dist/` 五件产物齐全（§1.3 产物表）。
4. **生成校验和**：`Get-FileHash dist\* -Algorithm SHA256`（Git Bash 可用 `sha256sum dist/*`），输出留作 Release notes 用。
5. **建 draft Release**：以 tag 为目标新建 **draft**，标题 `SyncReader v1.0.0`，按下方模板填 notes，上传 `dist/` 全部产物。
6. **自查清单**（publish 前逐项核对）：
   - [ ] 产物 5 件齐全，文件名与 §1.3 命名契约一致；
   - [ ] 体积门通过：每 APK ≤60MB、安装器 ≤120MB（NFR-04）；
   - [ ] APK 为**正式签名**（非 debug 回退，§2.6）；
   - [ ] CHANGELOG 含本版本条目；
   - [ ] Release 页校验和与实文件一致；
   - [ ] （有条件时）干净环境验证：Windows 安装器装/卸正常、便携包解压可运行、Android 真机侧载可启动。
7. **Publish**：确认无误后发布 draft，正式对外可见。

### Android 侧载安全提示

- 只从本仓库**官方 Releases 页**下载 APK，第三方转载渠道不背书；
- 安装前核对 SHA-256 与 Release 页公布值一致；
- 系统提示「Play Protect 未验证 / 未知开发者」属自签分发的正常现象；
- 若浏览器下载后丢失 `.apk` 后缀，手动补全后再安装。
