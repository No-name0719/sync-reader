## 4. VS Build Tools（Windows 桌面构建）

静默安装命令（**需管理员权限**，在管理员终端执行，或在普通终端运行后确认 UAC 弹窗）：

```powershell
D:\softwares\node_env\downloads\vs_BuildTools.exe `
  --quiet --wait --norestart --nocache `
  --installPath "D:\softwares\node_env\vs2022" `
  --add Microsoft.VisualStudio.Workload.VCTools --includeRecommended
```

- 耗时约 15-30 分钟（下载 ≈2GB，占用 ≈8GB）；`--includeRecommended` 含 MSVC v143 + Windows 11 SDK + CMake。
- 安装后 `flutter doctor` 应显示 "Visual Studio - develop Windows apps"；
  首次 `flutter build windows` 会拉取 Windows 桌面依赖（落 `PUB_CACHE`，仍在 D 盘）。
- 未安装时 `flutter build windows` 报错，但 `flutter analyze/test`、Android 与 CI 构建不受影响。

### 6.1 Gradle 分发：services.gradle.org 直连不通

本机网络下载 `services.gradle.org` 恒为 0 字节（构建报 `org.gradle.wrapper.Install` 异常）。
处理方式（不改仓库内 `gradle-wrapper.properties`，保持对 CI 友好）：
手动从腾讯镜像下载对应版本 zip，放进 wrapper 缓存目录，wrapper 检测到本地 zip 即跳过下载：

```bash
# 版本与 hash 目录以 android/gradle/wrapper/gradle-wrapper.properties 的 distributionUrl 为准
D=/d/softwares/node_env/gradle-home/wrapper/dists/gradle-9.3.1-all/9ot9r568e8zfvvd4mn8rbu1j0
curl -L -o "$D/gradle-9.3.1-all.zip" "https://mirrors.cloud.tencent.com/gradle/gradle-9.3.1-all.zip"
rm -f "$D"/*.part "$D"/*.lck
```

### 6.2 Flutter engine 构件：download.flutter.io 必须走镜像

构建 APK 时 gradle 从 `storage.googleapis.com/download.flutter.io` 下载 engine jar
（`io/flutter/{abi}_debug/...`），该域名直连会**挂起无超时**（表现为
`Running Gradle task 'assembleDebug'` 卡住，jstack 显示在等 artifact transform）。
flutter 的 gradle 插件原生读取 `FLUTTER_STORAGE_BASE_URL` 环境变量切换 maven 源
（`FlutterPlugin.kt`），已持久化为用户环境变量。

排障命令备忘（卡死时）：

```bash
# 1) 看是否卡在下载（.tmp 目录应有增长；无增长且 CPU 不动 = 挂起）
ls -la $GRADLE_USER_HOME/.tmp/
# 2) 全部清掉 java/dart 进程后，带镜像变量重跑
powershell -c "Get-Process java,dart -ErrorAction SilentlyContinue | Stop-Process -Force"
export FLUTTER_STORAGE_BASE_URL=https://storage.flutter-io.cn
```

另：强杀 gradle daemon 后立刻重跑可能继承脏状态继续挂起，清进程再跑即可。

### 6.3 Windows 构建"需要符号链接支持"（开发者模式）的免管理员绕过

本机**未开启** Windows 开发者模式且无管理员权限时，`flutter build windows` 一旦有插件就会失败：
`Building with plugins requires symlink support`（flutter_tools 需要在
`windows/flutter/ephemeral/.plugin_symlinks/` 下创建真符号链接，特权操作）。

绕过方案（已验证，2026-10-26）：**junction（目录联接）不需要特权**，且 Dart 的
`FileSystemEntity.typeSync(followLinks: false)` 把 junction 识别为 `link`。flutter_tools 的
重建逻辑对"已是 link 且目标一致"的条目会跳过——因此手动用 junction 预建全部插件链接即可：

```bash
cd apps/sync_reader
python - <<'EOF'
import json, os, subprocess
d = json.load(open('.flutter-plugins-dependencies', encoding='utf-8'))
base = os.path.abspath('windows/flutter/ephemeral/.plugin_symlinks')
os.makedirs(base, exist_ok=True)
for p in d['plugins']['windows']:
    link = os.path.join(base, p['name'])
    if not os.path.exists(link):
        subprocess.run(['cmd', '/c', 'mklink', '/J', link, os.path.abspath(p['path'])])
EOF
```

注意：`.plugin_symlinks` 在 ephemeral（gitignore）下，属机器本地产物；插件清单变化
（pubspec 增删插件触发 `.flutter-plugins-dependencies` 变更）会被 flutter 强制清空重建而再次失败，
届时重跑上述脚本即可。**根治**：以管理员开启开发者模式（`start ms-settings:developers`）。

### 6.3.1 pdfrx 的 pdfium 下载卡死：手动预置（已验证，2026-10-26）

pdfrx 的 `windows/CMakeLists.txt` 首次配置时会从 GitHub 下载 `pdfium-win-x64.tgz`（约 3MB），
本机直连 GitHub 会在中途断流卡死。绕过：手动下载后解压到 CMake 期望位置，CMake 检测到
`bin/pdfium.dll` 已存在即跳过下载（输出 `Use existing precompiled PDFium.`）：

```bash
# 目标目录（相对 apps/sync_reader）：build/windows/x64/pdfium/chromium%2F7202/
D=build/windows/x64/pdfium/chromium%2F7202
# 直连失败时用镜像（两者任选，ghfast.top / gh-proxy.com 均已验证 200）
curl -L -o "$D/pdfium-win-x64.tgz" "https://ghfast.top/https://github.com/bblanchon/pdfium-binaries/releases/download/chromium%2F7202/pdfium-win-x64.tgz"
python -c "import tarfile; tarfile.open(r'$D/pdfium-win-x64.tgz','r:gz').extractall(r'$D')"
```

坑：Git Bash 的 GNU tar 对该归档会**误报** `unexpected end of file`（python gzip 可完整读取
6.45MB 全流），校验一律用 python `gzip`/`tarfile`。该目录在 `build/` 下属临时产物，
`flutter clean` 后需重新预置。

Android 侧同理：`flutter build apk` 时 pdfrx 按 ABI 下载 `pdfium-android-{arm64,arm,x86,x64}.tgz`。
**注意落点**：AGP 每次 configure 会清空 `.cxx/`，预置到那里的文件会被抹掉；收编包的
CMakeLists 已打补丁把共享缓存目录 `.lib/chromium%2F7202/<abi>/libpdfium.so` 也视为有效缓存
（见该文件 `SyncReader patch` 注释），预置到 `.lib` 才持久：

```bash
cd packages/third_party/pdfrx/android
LIB=".lib/chromium%2F7202"
for pair in "arm64-v8a:arm64" "armeabi-v7a:arm" "x86:x86" "x86_64:x64"; do
  abi="${pair%%:*}"; suf="${pair##*:}"
  mkdir -p "$LIB/$abi"
  curl -L -o "$LIB/$abi.tgz" "https://ghfast.top/https://github.com/bblanchon/pdfium-binaries/releases/download/chromium%2F7202/pdfium-android-$suf.tgz"
  python -c "import tarfile,os; d=os.path.join(r'.lib','chromium%2F7202',r'$abi'); tarfile.open(d+'.tgz','r:gz').extractall(d)"
  # 归档内是 <abi>/lib/libpdfium.so，需上移一层与 CMake 预期一致
  f="$LIB/$abi/lib/libpdfium.so"; [ -f "$f" ] && mv "$f" "$LIB/$abi/libpdfium.so"
  rm -f "$LIB/$abi.tgz"
done
```

CI（GitHub Actions runner）网络直连 GitHub 无碍，无需预置；Windows 构建同理由收编补丁
+ 预置脚本兜底（见 §6.3/§6.3.1）。

### 6.4 本机 cmd AutoRun 注册表污染（无管理员，待修复）

`HKLM\Software\Microsoft\Command Processor\AutoRun = "chcp 65001"`（缺 `>nul`）会让每个
cmd 子进程 stdout 多打一行 `Active code page: 65001`，污染依赖 cmd 输出解析的工具链
（如 pdfrx 2.x native assets 的 vcvars64.bat 探测，见 [07-R15](./07-风险与待确认问题.md)）。
修复需管理员执行：

```powershell
reg add "HKLM\Software\Microsoft\Command Processor" /v AutoRun /t REG_SZ /d "chcp 65001 >nul" /f
```
