# 06 - 自建服务端设计与部署

> **TL;DR**：自建服务器用 **Go 编写、编译为单静态二进制、SQLite 存元数据账本、文件系统存书籍**，提供**自定义 REST API**（协议选型对比见 [02 §D4.2](./02-技术选型.md)）。服务端只做四件事：**带乐观锁（CAS）的元数据存储、增量变更查询（游标）、书籍文件托管（支持 Range）、设备级 token 鉴权**；**不做冲突裁决**（合并永远在客户端，保证与 WebDAV 模式语义一致，见 [04 §6](./04-同步引擎与冲突解决.md)）。支持多用户（默认关闭注册）与 `SINGLE_USER` 配对码免密模式。部署形态：Docker Compose（推荐）/ 单二进制 + systemd / Tailscale 内网直连。本文给出端点级 API 规格、鉴权流程与三种部署方式的完整配置示例。

---

## 1. 职责边界

| 做 | 不做 |
| --- | --- |
| 元数据 JSON 的版本化存取（CAS：`If-Match: rev`） | 冲突合并（客户端职责，[04 §6](./04-同步引擎与冲突解决.md)） |
| 全局递增序列号 `seq`，支撑增量游标 | 内容理解（不解析书、不算进度） |
| 书籍文件存取（`Range` 下载、上传后校验 SHA-256） | 任何形式的收费、遥测、外呼 |
| 设备注册/吊销、JWT 签发 | 文件格式校验之外的业务校验 |
| 用户隔离（多用户） | — |

存储布局（服务端磁盘，与客户端云目录概念对应）：

```
{DATA_DIR}/
├── sync-reader.db               # SQLite：users / devices / meta_index(seq, bookId, rev, deleted, size, hash) / refresh_tokens
└── users/{userId}/
    ├── meta/{bookId}.json       # 与云端布局一致（[05 §1](./05-元数据Schema与云端目录布局.md)）
    ├── books/{bookId}.{ext}
    └── tmp/
```

> `meta_index` 是加速表（避免每次增量查询扫描全部 JSON），以 `rev/seq` 为权威来源，JSON 文件为正本；两者不一致时以 JSON 为准并在自检时修复。

## 2. API 规格（v1）

Base path：`/api/v1`。除 `auth/*`、`health` 外均需 `Authorization: Bearer <accessToken>`。所有响应 `Content-Type: application/json; charset=utf-8`，错误体统一 `{"error": {"code": "REV_CONFLICT", "message": "..."}}`。

### 2.1 端点一览

| 方法 | 路径 | 说明 | 成功 |
| --- | --- | --- | --- |
| POST | `/auth/login` | 用户名+密码+设备名 登录 | 200，token 对 |
| POST | `/auth/pair` | `SINGLE_USER` 配对码换 token | 200，token 对 |
| POST | `/auth/refresh` | 刷新 accessToken | 200，token 对 |
| POST | `/auth/logout` | 吊销当前设备 refreshToken | 204 |
| GET | `/library` | 取 `library.json`（schemaVersion/libraryId） | 200 |
| GET | `/sync/changes?cursor={seq}&limit=200` | **增量元数据同步**：返回 seq > cursor 的全部变更（含 tombstone，含 meta 全文），按 seq 升序 | 200 |
| GET | `/meta/{bookId}` | 单本 meta；`ETag: "rev:{n}"` | 200 / 304 |
| PUT | `/meta/{bookId}` | 写 meta；**必须**带 `If-Match: "rev:{n}"`（新建传 `"rev:0"`） | 204 / **409**（body=当前 meta） |
| GET | `/books/{bookId}?ext=epub` | 下载正文；支持 `Range`；`ETag: "sha256:..."` | 200 / 206 / 304 |
| PUT | `/books/{bookId}?ext=epub&hash={sha256}` | 上传正文（整体）；服务端落地后校验哈希，不符删稿返回 422 | 204 / 422 |
| DELETE | `/books/{bookId}` | 删除正文文件（仅"清理孤儿文件"工具调用，删除书走 tombstone，[04 §7](./04-同步引擎与冲突解决.md)） | 204 |
| GET | `/health` | 存活检查（Docker healthcheck 用） | 200 |

### 2.2 关键交互示例

**增量同步（客户端每 15min / 启动时）**

```http
GET /api/v1/sync/changes?cursor=1042&limit=200
Authorization: Bearer eyJ...

200 OK
{
  "cursor": 1047,
  "hasMore": false,
  "changes": [
    { "bookId": "01JB...", "seq": 1044, "rev": 42, "deleted": false,
      "meta": { "...完整 meta JSON，同 05 §2..." } },
    { "bookId": "01JC...", "seq": 1046, "rev": 7,  "deleted": true,
      "meta": { "...tombstone 形态 meta..." } }
  ]
}
```

客户端语义：`changes[].meta` 直接交给 DiffEngine（等价于 WebDAV 模式的"PROPFIND + 条件 GET 全过程"），`cursor` 持久化到 `sync_cursor` 表（[05 §5](./05-元数据Schema与云端目录布局.md)）。分页：`hasMore=true` 时以返回的新 cursor 续拉。

**乐观锁写入（服务端唯一的"裁决"参与点）**

```http
PUT /api/v1/meta/01JB... HTTP/1.1
If-Match: "rev:40"
Content-Type: application/json

{ ...meta（rev=41）... }

→ 204：写入成功，服务端分配 seq=1048，返回 ETag: "rev:41"
→ 409：{"error":{"code":"REV_CONFLICT"}} + body 为服务端当前 meta
        客户端走 [04 §6] 合并后以新的 If-Match 重试一次
```

**正文上传**

```http
PUT /api/v1/books/01JB...?ext=epub&hash=sha256:9f2c...a1
Content-Type: application/octet-stream

<二进制>
→ 204（服务端落地 users/{uid}/books/01JB....epub 并校验 sha256）
→ 422：哈希不符（客户端应重传）
```

## 3. 鉴权与多用户

### 3.1 令牌模型

| 项 | 设计 |
| --- | --- |
| 密码存储 | Argon2id（默认参数），禁用弱哈希 |
| accessToken | JWT HS256（`JWT_SECRET`），15 分钟有效，载荷含 `uid/deviceId` |
| refreshToken | 32 字节随机，**服务端只存哈希**，30 天有效；每设备一条，可单独吊销；刷新时轮换（旧 refresh 立即失效，防重放） |
| 设备 | 登录即注册设备（deviceName + ULID），设置页可见/可踢（服务端 web 面板 v2，v1 用 CLI `serverctl devices list|revoke`） |
| 传输 | 生产必须 HTTPS（Caddy 自动证书）或 Tailscale 内网（WireGuard 已加密，可用 http） |

### 3.2 多用户

- `REGISTRATION_OPEN=true` 时开放 `POST /auth/register`（v1 默认 **false**，用户由管理员 CLI `serverctl user add` 创建）；
- 数据按 `userId` 目录级隔离，API 层强校验归属；
- **`SINGLE_USER=true` 家用模式**：启动时若库内无用户，自动建单用户并在控制台打印**一次性配对码**（10 分钟有效）；客户端在配置向导输入该码（`POST /auth/pair`）即完成绑定，全程无需设密码——家用/内网场景零门槛。

## 4. 部署方案

### 4.1 Docker Compose（推荐）

```yaml
# docker-compose.yml
services:
  sync-reader-server:
    image: syncreader/server:1        # 或 ghcr.io/<you>/sync-reader-server
    container_name: sync-reader
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      PORT: "8080"
      DATA_DIR: /data
      SINGLE_USER: "true"             # 家用单用户；多用户设 false 并用 CLI 建号
      REGISTRATION_OPEN: "false"
      JWT_SECRET: "change-me-64hex"   # 首次生成后固定；留空则自动生成并持久化到 /data
      TZ: Asia/Shanghai
    volumes:
      - ./data:/data
    healthcheck:
      test: ["CMD", "/app/server", "health", "--port", "8080"]
      interval: 30s
      timeout: 5s
      retries: 3
```

镜像构建：多阶段 Dockerfile（golang 构建层 → `FROM scratch`/`distroless` 运行层，仅二进制 + ca-certificates，最终镜像 ≈ 15MB）。

### 4.2 反向代理（公网云服务器，可选）

```caddy
# Caddyfile —— 自动 HTTPS（Let's Encrypt）
sync.example.com {
    reverse_proxy 127.0.0.1:8080
    request_body {
        max_size 600MB          # 覆盖单文件上限（NFR-07：500MB）
    }
}
```

### 4.3 Tailscale 纯内网（家用机/NAS）

1. 家用机与所有阅读设备加入同一 tailnet；
2. 家用机运行容器/二进制（监听 `0.0.0.0:8080`，无需公网暴露、无需证书）；
3. 客户端配置地址 `http://<机器的 tailnet 名或 100.x.y.z>:8080`；
4. 优点：零端口暴露、传输已加密、换网络（4G/Wi-Fi）均可达；手机端 Tailscale App 保持后台即可。

### 4.4 裸机二进制 + systemd

```bash
curl -LO https://.../sync-reader-server-linux-amd64   # 或 arm64，单文件
sudo install sync-reader-server-linux-amd64 /usr/local/bin/sync-reader-server
sudo useradd -r -s /usr/sbin/nologin syncreader && sudo mkdir -p /var/lib/sync-reader
sudo chown -R syncreader /var/lib/sync-reader
sudo systemctl enable --now sync-reader
```

```ini
# /etc/systemd/system/sync-reader.service
[Unit]
Description=SyncReader server
After=network-online.target

[Service]
User=syncreader
Environment=DATA_DIR=/var/lib/sync-reader
Environment=PORT=8080
Environment=SINGLE_USER=true
ExecStart=/usr/local/bin/sync-reader-server
Restart=on-failure
HardeningFlags=yes   # NoNewPrivileges / ProtectSystem=strict 等按 go 调优模板

[Install]
WantedBy=multi-user.target
```

### 4.5 备份与升级

- 备份：`serverctl backup /backup/dir`（内部：SQLite `VACUUM INTO` + 文件目录打包，一致性快照）；用户亦可直接停容器后整目录拷贝；
- 升级：单二进制/镜像替换即完成；服务端无 schema 破坏性迁移承诺时向后兼容一个次版本（meta 正本在 JSON 文件，服务端库损坏可全量重建 `meta_index`：扫描 users/* 重建索引的 `serverctl reindex`）。

## 5. 服务端实现要点（Go）

| 关注点 | 方案 |
| --- | --- |
| 路由 | `chi`（标准 net/http 兼容、中间件成熟） |
| SQLite 驱动 | `modernc.org/sqlite`（纯 Go、CGO-free，交叉编译 linux/arm64 无痛） |
| 并发写 | SQLite WAL + 单写者串行化（meta PUT 走写队列）；文件写 `tmp → rename` 原子提交 |
| 上传完整性 | 落盘流式计算 SHA-256 与 query `hash` 比对（§2.2） |
| Range 下载 | `http.ServeContent` 原生支持 Range/If-Range |
| 限流 | 每设备令牌桶（默认 60 req/min），429 + `Retry-After`（客户端已按 [04 §8.4](./04-同步引擎与冲突解决.md) 处理） |
| 日志 | 结构化（slog），凭据字段零落盘 |
| 可观测 | `/health` + 每日请求数/流量计数日志行（用户自查用） |

## 6. 客户端配置方式（FR-503 的实现规格）

配置向导（自建模式）字段：`地址`（`http(s)://host:port`）、`模式`（账号密码 / 配对码）、凭据 → "测试连接"（调 `/health` + `/library` + 一次 401 探测区分地址错误/凭据错误）→ 成功后进入首次同步流程（[04 §5.2](./04-同步引擎与冲突解决.md)）。明文 http 时弹安全确认对话框（NFR-03）。
